1M0 收尾 · 概念验证固化

M0概念验证
目标：固化 sim 引擎与 MVP UI，补齐当前已知简化点，作为后续阶段的稳定基座。
验收：一场比赛可生成 PBP + box score（已达成）；补：轮换/犯规/加时

1.1 sim 引擎基础补强

核心任务清单
  • 球员轮换：实现按 Lineup.minutes 分配上场时间；节间/死球换人；替补球员进入 onCourtPlayers。当前 onCourtPlayers 仅返回首发，需改为根据累计出场时间动态选择。
  • 犯规系统：累计个人犯规，6 犯自动离场（强制换人）；团队犯规达阈值触发罚球（当前 foul 事件仅扣描述不影响流程）。
  • 加时赛：4 节结束平分时进入 OT（5 分钟 = 约 10 回合），最多 2 个 OT。
  • 时间模型：保留回合数近似，但把 formatClock 改为基于已消耗回合比例 + 随机微调，使时钟更自然。
  • 关键时刻 clutch：最后 2 分钟分差 ≤5 时，投篮选择权重向 clutch 能力高的球员倾斜，命中率乘 clutch 修正。
  • 特质 traits：预留的 traits: string[] 接入 3-5 个基础特质（神射手/禁区霸主/铁人/关键先生），在 shotChance/effectiveAbilities 中生效。

1.2 前端基座完善

  • 移动端适配：确认 .stats-table、.pbp-dual、底部状态栏在 375px 宽度下不溢出；PBP 双栏在窄屏降为单栏时间线。
  • 加载/空状态：球队列表、战术列表、sim 结果的骨架屏与错误重试。
  • 可访问性：Tab 键导航、ARIA 标签、颜色对比度（当前橙色 #ff6b35 在深色背景对比度需复核）。

1.3 交付物

文件/模块变更
packages/shared/src/sim.ts轮换、犯规、加时、clutch、traits
packages/shared/tests/新增轮换/犯规/加时/特质单测
packages/web/src/styles.css移动端响应式完善
验收标准：① 6 犯球员自动离场并触发换人；② 平局进入 OT；③ clutch 时段关键球员出手占比 ≥ 非 clutch 时段；④ 375px 宽度下无横向滚动条；⑤ 确定性测试 100% 通过（新增逻辑不得破坏确定性）。

2M1 · 闭合核心循环（单机赛季）

M1闭合核心循环
目标：实现日循环 + 阵容/战术/训练/球探可玩（单机 vs AI），一个赛季走完，升降级生效。
验收：一个赛季可走完，升降级生效

2.1 数据持久化层（P0 阻塞项）

数据库设计与 ORM
  • ORM 选型：Prisma（类型安全 + 迁移工具 + 与 TS 全栈契合）。
  • 核心表：users、teams、players（abilities JSONB）、lineups、tactics、seasons、leagues、matches、match_results（pbp JSONB、box_score JSONB）、standings、player_stats_agg（赛季聚合）。
  • 迁移：prisma migrate dev 初始化 schema；seed 脚本写入 6 支初始球队。
  • TeamService 改造：从 generateAllTeams 内存生成 → Prisma 查询；保留生成器作为 seed 工具。
  • Redis 缓存：球队详情、战术列表缓存（TTL 5min），减少 DB 压力。

2.2 用户与球队归属

  • 认证：JWT（access + refresh）；邮箱注册/登录；密码 bcrypt。
  • 球队绑定：用户创建/加入世界时分配一支球队（先开放全部 6 支供选择，后改为选秀分配）。
  • 权限：用户只能修改自己球队的 lineup/tactic；他人球队只读。

2.3 赛季与全球时钟

赛季编排核心任务
  • 赛程生成：单循环（6 队 = 15 场）或双循环（30 场）；固定全局时钟节点（每日 02:00 UTC 结算）。
  • 每日结算引擎：Worker 拉取当日未结算 matches → 调用 simulate() → 写入 match_results → 更新 standings。
  • 积分榜：胜率 / 净胜分 / 相互战绩排序；升降级（当前 6 队可先做 2 升 2 降或仅展示排名）。
  • 赛季交接：常规赛结束 → 季后赛（6 队可做前 4 单败淘汰）→ 休赛期 → 下赛季。

2.4 经理玩法核心四件套

阵容管理
设置首发 5 人 + 替补轮换分钟 + 伤病/NOT 名单。前端 LineupEditor 组件。
战术配置
从 20 预设中选择主战术 + 可微调参数（M1 用预设，M2 开放编辑器）。
训练系统
每周分配训练点到 5 组能力；产出微弱能力成长（±1-2）。参考训练系统设计.html。
球探系统
派遣球探考察指定球员/球队，揭示部分隐藏属性（The Fog）。参考球探系统设计.html。

2.5 AI 经理（单机填充）

  • AI 经理自动设置 lineup（按 OVR 排序）、选战术（随机或按球队风格）、分配训练点。
  • AI 决策需可配置难度（简单/普通/困难），影响战术合理性。

2.6 前端页面

  • 登录/注册页 + 世界/赛季主页（积分榜 + 今日赛程 + 我的球队卡片）。
  • 球队管理页：LineupEditor + TacticSelector + TrainingPanel + ScoutingPanel（Tab 切换）。
  • 赛程/结果页：日历视图 + 每场比赛的 PBP/Box Score 回看。

2.7 交付物与验收

验收标准：① 用户登录后看到自己球队与积分榜；② 可编辑 lineup/tactic/training/scouting 并持久化；③ 触发"推进一日"后，当日比赛自动结算、积分榜更新；④ 走完一个完整赛季，季后赛产生冠军，下赛季积分榜重置；⑤ 升降级规则生效。

3M2 · 联机 + 升降级

M2联机 + 升降级
目标：多玩家同联赛、AI 经理填充、实时观战、跨经理交易。
验收：1 个 16 人联赛跑完一季

3.1 多玩家世界

  • 世界扩容：单世界 16 支球队（真实玩家 + AI 填充）；联赛金字塔 L1/L2 两级。
  • 世界生成：新玩家加入时分配到有空位的世界或新世界；世界内经济封闭。
  • AI 经理替换：玩家离线/退坑时，AI 接管其球队，保持联赛完整。

3.2 实时观战

SSE PBP 推送
  • 服务端：比赛进行时通过 SSE（/api/matches/:id/stream）逐条推送 PBP 事件。
  • 客户端：现有 LiveMatch 组件从"回放全量 PBP"改为"订阅 SSE 流式渲染"，shot clock 实时倒计时。
  • 降级：SSE 不可用时回退为全量拉取（当前模式）。

3.3 跨经理交易系统

  • 报价流程：发起方提交筹码（球员+选秀权+现金）→ 对方接收 → 三轮还价（限时 24h）→ 达成/拒绝。
  • 薪资匹配：交易双方薪资总额差 ≤ 25%（参考经济系统设计 §4）。
  • AI 交易：AI 经理根据球队需求（缺人位置/薪资空间）接受或还价。
  • 防共谋：失衡交易（筹码价值差距 > 阈值）触发人工复核队列。

3.4 高级战术编辑器

  • 从预设选择升级为可视化参数调整（滑块 + 实时预览影响）。
  • 战术反制：可设置针对对方特定战术的应对策略（如对方跑轰→收缩内线）。

3.5 交付物与验收

验收标准：① 16 人联赛（含 AI）跑完一整赛季；② 玩家可发起交易并在 24h 内收到 AI 回应；③ 实时观战页面 PBP 流式更新，延迟 < 1s；④ 升降级后 L2 前 2 升入 L1。

4M3 · 生涯 + 青训

M3生涯 + 青训
目标：生涯弧线 + 青训学院 + 金字塔（高中+大学）+ 传承。
验收：一代核心可养成至退役并传承

4.1 球员生涯弧线（Career Arc）

  • 五阶段：新秀(19-22) → 上升(23-27) → 巅峰(28-32) → 下滑(33-36) → 退役(37+)。
  • 动态成长：每赛季根据年龄 + 训练量 + 出场时间 + 伤病，能力值自然成长或衰退。
  • 退役：37+ 岁且能力跌破阈值时自动退役，进入传奇名册。

4.2 青训学院

  • 球队拥有青训学院，每年产出 1-3 名新秀（潜力随机）。
  • 青训投入（资金）影响新秀上限。

4.3 业余金字塔（Grassroots）

  • 高中联赛 → 大学联赛 → NBA（世界顶级联赛） 三级晋升。
  • 玩家球员化身可从高中打起，逐步晋升（三身份系统的"球员化身"线）。
  • M3 先做经理视角的选秀与青训，球员化身线放 M3 后期。

4.4 选秀系统

  • 每年休赛期举办选秀：青训产出 + 其他世界球员流入。
  • 乐透抽签（战绩倒序权重）。

4.5 签约与合同

  • 合同年限 + 年薪 + 球员选项/球队选项 + 交易否决权。
  • 自由市场签约（工资帽约束）。

4.6 交付物与验收

验收标准：① 一名 19 岁新秀经 5 赛季训练后能力显著提升；② 37 岁老将自动退役；③ 选秀大会产生新秀并签约；④ 青训学院产出可用球员。

5M4 · 商业化 + PWA

M4商业化 + PWA
目标：Credits/VIP、外观、PWA 安装、推送。
验收：移动端可用、付费链路通

5.1 经济与货币

  • 双货币：Coins（游戏内产出）+ Credits（付费购买）。
  • VIP 体系：月卡 / 季卡，提供便利性（额外球探名额、训练加速），不卖强度。
  • 外观付费：球队球衣、球馆皮肤、头像框。

5.2 PWA 与推送

  • Service Worker：离线缓存核心页面（阵容/战术/积分榜）。
  • Web Push：比赛结算推送、交易报价推送、赛季关键节点。
  • 安装到主屏：manifest + iOS/Android 兼容。

5.3 支付集成

  • Stripe（国际）+ 支付宝/微信（国内）沙箱环境。
  • 订单服务端校验，Credits 发放走服务端权威。

5.4 交付物与验收

验收标准：① Credits 购买链路在沙箱环境闭环；② PWA 可安装到手机主屏，离线可查看球队；③ 推送通知在比赛结算后到达。

6M5 · 软启动 / 封测

M5软启动 / 封测
目标：平衡调参、反作弊、留存观测、多世界。
验收：次留/7 留达标

6.1 平衡调参

  • 海量自动对局：10 万场 sim 回归测试，统计得分/命中率/篮板等分布是否符合真实篮球区间。
  • 灰度调参：SimConfig 热更新，A/B 测试不同参数集。

6.2 反作弊

  • 服务端权威：所有 sim 结果由服务端产生，客户端无法篡改。
  • 风控：多开检测、异常交易人工复核、sim 结果审计（rngLog 可重放）。

6.3 留存与数据观测

  • 埋点：DAU、次日留存、7 日留存、赛季完成率、付费转化。
  • 看板：Grafana + 自定义留存漏斗。

6.4 多世界扩容

  • 支持同时运行多个世界，每个世界独立结算与经济。
  • 世界间球员/资产不可转移。

6.5 交付物与验收

验收标准：① sim 自动对局统计分布在合理区间；② 人工无法通过客户端篡改比赛结果；③ 封测期间次留 ≥ 35%，7 留 ≥ 15%；④ 3 个世界并行运行无干扰。

7横切工程能力

以下能力贯穿所有阶段，需持续建设。

7.1 CI/CD

  • 当前 CI：lint + test + build。M1 起增加：Prisma 迁移检查、Docker 镜像构建、部署到 staging。
  • sim 确定性测试作为 CI 硬门槛（已有）。

7.2 监控与日志

  • 结构化日志（pino）→ ELK / Loki。
  • Worker 监控：队列长度、处理耗时、失败率告警。
  • API 监控：P99 延迟、错误率。

7.3 安全

  • JWT + 速率限制 + SQL 注入防护（Prisma 参数化）。
  • 敏感数据加密（密码 bcrypt，密钥环境变量）。
  • CORS 白名单。

7.4 性能预算

指标预算说明
单场 sim 耗时≤ 50ms纯函数，需支持百万场/日结算
结算窗口≤ 10min16 队 × 1 日赛程并行
API P99≤ 300ms含 DB 查询 + 缓存
首屏加载≤ 2s (4G)PWA + 代码分割
PBP 推送延迟≤ 1sSSE 实时观战

7.5 文档与可维护性

  • API 文档：Swagger / OpenAPI（NestJS 装饰器自动生成）。
  • sim 引擎的每个修正参数附注释与设计文档锚点。
  • ADR（架构决策记录）：ORM 选型、通信协议选型等。

8测试与质量策略

8.1 分层测试金字塔

层级工具覆盖
单元测试Vitestsim 引擎纯函数、生成器、战术修正、lib 工具（目标 ≥ 80%）
集成测试Supertest + TestcontainersAPI 端点 + DB 读写 + Worker 结算流程
E2E 测试Playwright核心玩家路径：登录→排阵→结算→看战报
回归测试Vitest（批量）10 万场 sim 统计分布校验（M5 调参用）

8.2 sim 确定性守护

  • 现有 12 项确定性测试必须 100% 通过，CI 阻断。
  • 新增逻辑（轮换/犯规/加时）须补充确定性测试，确保同 seed 同输出。
  • 浮点运算：统一使用 Math.round 或整数定点，避免跨平台浮点差异。

8.3 性能回归

  • CI 中加入 sim 耗时基准：1000 场平均耗时 > 50ms 则告警。
  • 结算窗口压测：16 队赛季一日赛程在 10min 内完成。

9风险与应对

风险概率影响应对
sim 平衡难收敛高高纯函数 + 海量自动对局回归 + 灰度调参；M1 起每阶段跑分布校验
冷启动玩家稀疏中高AI 经理填充联赛，随真实玩家增加逐步替换；单世界先开
反外挂/多开/共谋中高服务端权威 sim + 账号风控 + 失衡交易人工复核 + rngLog 审计
版权低中虚构联赛/球员，致敬风格不照搬真实标识
留存中高每日时钟 + 王朝叙事 + 实时观战 + 升降级赌注制造回流钩子
经济通胀中中赛季结算消耗 + 球员自然流出 + 薪资服务端锚定 + 奢侈税
多人公平低高固定全球时钟 + 世界内封闭经济 + 付费不卖强度
Prisma 迁移风险中中M1 初期用单环境，staging 验证后再上生产；迁移脚本备份
核心原则：sim 引擎必须保持纯函数 + 确定性，这是防作弊、可重放、灰度调参的根基。任何对 sim 的修改都必须通过确定性测试。
