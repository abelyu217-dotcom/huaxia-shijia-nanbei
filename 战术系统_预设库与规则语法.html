1预设库分类体系

预设库从原 9 套扩展到 20 套，按四个维度组织。每套预设都是"起点而非终点"——玩家可直接使用，也可基于预设修改后另存为自定义战术存档。

1.3 预设参数映射规范

每套预设的参数映射遵循统一结构，确保 sim engine 能一致解析：

PresetTactic = { id: string, // 唯一标识，如 "run_and_gun" name: string, // 中文名 nameEn: string, // 英文名 category: "off" | "def" | "mix" | "spec", tempo: "slow" | "mid" | "fast" | "ultra_fast", // —— L1 基础倾向 —— offenseTendency: "outside" | "balanced" | "inside", defenseTendency: "press" | "balanced" | "pack", // —— L2 高级参数 —— params: { tendencyMod: { three, midrange, inside, drive, postup }, // 出手倾向倍率 fastBreakChance, pickRollChance, threeFreq, defenseContest, helpDefChance, stealChance, blockChance, possessionTimeDelta, // 回合耗时偏移（秒） conditionLossMul, // 体力消耗倍率 foulStrategy, // conservative/normal/aggressive rotationMode, // star/balanced/deep targetDef, // 对位针对性防守（可选） roleOverrides, // 战术角色覆盖（可选） }, // —— 元信息（非 sim 参数，用于 UI 展示与选用指南）—— meta: { rosterFit: [string], // 适用阵容特征 weakness: [string], // 风险代价 counters: [string], // 克制的预设 id counteredBy: [string], // 被克制的预设 id unlockCond: string, // 解锁条件 }, }
参数缺省规则：未列出的参数取默认值（tendencyMod=1.0、defenseContest=1.0 等）。预设只需声明非默认参数，保持定义简洁。

2进攻型预设详查

2.1 跑轰战术 Run & Gun

跑轰战术Run & GunOFF快节奏
offenseTendency=outside · defenseTendency=balanced · tempo=fast
极致的快节奏 + 三分火力。用速度制造转换进攻机会，半场以三分为主攻。体力消耗大，需要深度板凳支撑全场高强度跑动。
tendencyMod[three] = 2.8 // 三分倾向大幅提升 tendencyMod[inside] = 1.0 fastBreakChance = 2.1 // 快攻概率 ×2.1 threeFreq = "high" fastBreakPref = "high" conditionLossMul = 1.3 // 体力消耗 ×1.3 possessionTimeDelta = -4 // 回合耗时 -4s rotationMode = "deep"
适用阵容
三分射手群 + 快攻型后卫 + 深度板凳
风险代价
体力消耗大；半场进攻粗糙；命中率波动大
克制
慢节奏半场阵地（铁桶阵地）
被克制
压迫防守造失误（防守反击）

2.2 魔球理论 Moreyball

魔球理论MoreyballOFF快节奏
offenseTendency=outside · tempo=fast · threeFreq=high
极端三分 + 攻筐 + 快攻，彻底放弃中距离。需要大量优质三分射手和突破型后卫。高分高赔，命中率波动时比分大起大落。
tendencyMod[three] = 2.8 tendencyMod[midrange] = 0.3 // 中距离近乎禁用 tendencyMod[inside] = 1.2 // 攻筐仍保留 tendencyMod[drive] = 1.4 pickRollChance = 0.40 threeFreq = "high" pickRollFreq = "high" fastBreakChance = 1.5
适用阵容
3-4 名优质三分射手 + 突破型 PG + 空间型内线
风险代价
三分失准夜全队哑火；中距离真空被针对
克制
收缩护筐型防守（铁桶阵地）
被克制
外线压迫防守（锁死外线）

2.3 三角进攻 Triangle

三角进攻TriangleOFF慢节奏
offenseTendency=balanced · tempo=slow · pickRollFreq=mid
经典阵地配合体系，通过三角站位拉扯空间，强调高低位传递与弱侧空切。需要高 OffIQ 阵容执行复杂配合，出手质量高但回合耗时长。
tendencyMod[inside] = 1.3 tendencyMod[midrange] = 1.2 tendencyMod[postup] = 1.4 // 低位背打是三角轴心 pickRollChance = 0.25 possessionTimeDelta = +3 // 阵地耗时 +3s pass actionWeight = 1.2 // 传导权重提升 abilityBonus = 1.05 // 配合加成（高 OffIQ 阵容受益） conditionLossMul = 0.9 // 慢节奏省体力
适用阵容
高 OffIQ 球员 + 低位得分手 + 空间型侧翼
风险代价
回合耗时长，比分低；低 IQ 阵容执行失误多
克制
快节奏跑轰（拖慢对手节奏）
被克制
压迫防守打断传导（绞肉机）

2.4 挡拆主导 Pick & Roll

挡拆主导Pick & RollOFF中节奏
offenseTendency=balanced · tempo=mid · pickRollFreq=high
高频挡拆策应创造错位进攻，挡拆后持球人选择出手/传球/顺下。需要高质量挡拆执行者（PG + 内线挡拆人）。
pickRollChance = 0.45 // 45% 回合发起挡拆 tendencyMod[drive] = 1.3 // 挡拆后突破 tendencyMod[inside] = 1.2 // 顺下终结 pickRollFreq = "high" abilityBonus = 1.03 // 挡拆配合小幅加成 roleOverrides = [{ role: "roll_man" }, { role: "playmaker" }]
适用阵容
优质挡拆 PG + 顺下型内线 + 空间型射手拉开
风险代价
挡拆被换防体系消解；过度依赖挡拆执行者
克制
收缩护筐防守（错位打大打小）
被克制
无限换防（换防体系）

2.5 孤立单打 Iso Ball

孤立单打Iso BallOFF中节奏
offenseTendency=balanced · tempo=mid
清空一侧让核心持球单打，极少配合。最大化核心球员的个人能力，但进攻极度可预测。适合有顶级单打手的阵容。
primaryScorer = "star1" tendencyMod[drive] = 1.5 tendencyMod[midrange] = 1.3 pass actionWeight = 0.6 // 降传导 pickRollChance = 0.10 // 极少挡拆 fastBreakChance = 0.7 // 不追求快攻 roleOverrides = [{ role: "primary_scorer", target: "star1" }]
适用阵容
顶级单打手（高 Scoring/Drive）+ 空间型射手拉开
风险代价
进攻可预测；核心体力消耗大；队友参与感低
克制
单打手对位劣势时高效
被克制
包夹针对性防守（targetDef=double_team）

2.6 低位统治 Post Dominance

低位统治Post DominanceOFF慢节奏
offenseTendency=inside · tempo=slow
以内线背打为主攻轴心，低位吸引包夹后分球外线。需要统治级内线 + 外线射手群惩罚包夹。节奏慢但出手质量高。
tendencyMod[postup] = 2.0 tendencyMod[inside] = 1.5 tendencyMod[three] = 1.1 // 包夹分球三分 pickRollChance = 0.15 possessionTimeDelta = +2 roleOverrides = [{ role: "blue_collar", target: "center" }]
适用阵容
统治级内线（高 Inside/Postup）+ 外线射手惩罚包夹
风险代价
内线被包夹失误；节奏慢追分难
克制
小球阵容（内线体型劣势）
被克制
包夹+联防（区域联防）

3防守型预设详查

3.1 铁桶阵地 Iron Wall

铁桶阵地Iron WallDEF慢节奏
offenseTendency=inside · defenseTendency=pack · tempo=slow
降低节奏打半场阵地，内线攻筐为主。收缩防守保护禁区，放对方外线。适合内线强 + 对方三分弱的对手。
defenseTendency = "pack" tendencyMod[inside] = 2.0 threeFreq = "low" fastBreakPref = "low" possessionTimeDelta = +3 defenseContest[inside] = 1.2 // 禁区干扰提升 defenseContest[three] = 0.6 // 放空外线 helpDefChance = 1.5 // 协防集中在禁区 conditionLossMul = 0.85
适用阵容
护筐型内线 + 对方三分弱的对手
风险代价
放空三分被射手惩罚；节奏慢自身得分也低
克制
内线攻筐型进攻（低位统治）
被克制
三分火力型进攻（跑轰/魔球）

3.2 绞肉机 Grinder

绞肉机GrinderDEF慢节奏
offenseTendency=inside · defenseTendency=press · tempo=slow
内线强攻 + 全场压迫防守。犯规风险极高但防守压迫感拉满。适合身体对抗型阵容，拖慢比赛进入肉搏节奏。
defenseTendency = "press" foulStrategy = "aggressive" tendencyMod[inside] = 2.0 tendencyMod[postup] = 1.5 defFoulChance = 1.50 // 犯规概率 ×1.5 stealChance = 1.3 defenseContest = 1.05 fastBreakPref = "low" possessionTimeDelta = +2
适用阵容
身体对抗型阵容 + 板凳深度（犯规多需轮换）
风险代价
犯规麻烦主力下场；罚球送分
克制
传导配合型进攻（三角/普林斯顿）
被克制
快攻型进攻（跑轰——犯规送快攻）

3.3 区域联防 Zone Defense

区域联防Zone DefenseDEF中节奏
defenseTendency=pack · tempo=mid
2-3 联防护筐护板，区域负责而非人盯人。有效保护禁区与篮板，但外线轮转慢被三分惩罚。适合内线体型劣势或犯规麻烦时使用。
defenseMode = "zone_2_3" defenseContest[inside] = 1.3 defenseContest[three] = 0.7 // 外线轮转慢 reboundContest = 1.15 // 联防护板 helpDefChance = 1.3 stealChance = 0.8 // 联防抢断少 defFoulChance = 0.85 // 联防犯规少 matchupOverride = [] // 联防无对位
适用阵容
内线体型劣势 / 主力犯规麻烦 / 对方外线弱
风险代价
三分射手惩罚；联防轮转失误送空位
克制
内线背打型进攻（低位统治）
被克制
三分火力型进攻（魔球/跑轰）

3.4 换防体系 Switch All

换防体系Switch AllDEF中节奏

适用阵容
1-5 号位均可换防的侧翼型阵容（Switchable 1-5）

低位被大打小；体力消耗大
克制
挡拆主导型进攻（Pick & Roll）
被克制
低位背打型进攻（低位统治）

5预设克制矩阵与选用指南

5.1 核心克制关系矩阵

行=己方预设，列=对方预设。●=克制(胜率+5~10%)，○=被克制(胜率-5~10%)，─=均势。

三角○○───○──●─
挡拆────●───●○
铁桶○○─○──○●─●

防反●───●●──●─
锁外线●●──○─────
联防●●○○──○───

克制≠必胜：克制关系仅提供 ±5~10% 胜率修正，球员能力差距仍是主导因素。克制的意义在于"同水平对局中获取边际优势"，而非以弱胜强的银弹。

5.2 预设选用决策树

  • Q1: 阵容核心优势在哪？
    • 三分射手群→ 考虑 跑轰 / 魔球 / 锁外线（攻防两端利用外线）
    • 统治级内线→ 考虑 低位统治 / 铁桶阵地 / 三角进攻
    • 挡拆组合（PG+内线）→ 考虑 挡拆主导（注意对方是否换防体系）
    • 无明显核心 / 均衡阵容→ 考虑 全能均衡 / 动态进攻
  • Q2: 对方核心威胁是什么？
    • 三分火力强→ 锁外线 / 换防体系（外线压迫）
    • 内线统治→ 铁桶阵地 / 联防 / 砍鲨（低罚球时）
    • 挡拆主导→ 换防体系（消解挡拆）
    • 快攻型→ 铁桶阵地（拖慢节奏）/ 防守反击（对拼压迫）
  • Q3: 赛程与体力状况？
    • 背靠背 / 主力疲劳→ 巅峰保核（省体力）
    • 板凳深度优势→ 能量板凳 / 跑轰（深度轮换支撑高强度）

5.3 预设 vs 自定义的定位

预设是起点，自定义是终点：新手用预设快速上手，理解战术方向感；进阶玩家基于预设修改参数 + 叠加条件规则，打造针对自家阵容与对手的定制战术。预设确保"即使不编辑也有合理战术可用"，自定义确保"深度玩家有足够调优空间"。

6规则 DSL 总览

条件规则系统（战术系统设计 §6）从"结构定义"升级为完整的领域特定语言（DSL）。玩家通过 DSL 编写条件规则，经编译器校验后注入 sim engine 的战术参数修改层。

6.1 DSL 设计目标

  • 表达力：支持 AND/OR/NOT 嵌套条件、参数 set/multiply/add 动作、目标球员引用。
  • 安全性：沙箱执行，不可访问 sim 内部状态以外的数据；参数修改有上下限钳制。
  • 确定性：规则求值顺序固定，同一输入永远产出同一参数修改集，保证可复现。
  • 性能：每套战术存档最多 8 条规则，每条规则的条件求值 O(条件数)，sim 每回合检查成本可控。
  • 可读性：类自然语言语法，玩家无需编程基础即可编写。

6.2 DSL 编译流水线

// 玩家在 UI 编写规则文本 → 编译 → 字节码 → sim 运行时求值 [玩家编写] RuleText ↓ Lexer // 词法分析 → Token 流 ↓ Parser // 语法分析 → AST（遵循 BNF 文法） ↓ SemanticChecker // 语义校验（条件类型/参数名/值域/目标引用） ↓ Optimizer // 常量折叠 + 冗余条件消除 ↓ Codegen // 生成字节码（紧凑可序列化） [注入 sim] RuleBytecode ↓ Runtime // sim 每回合求值 → 参数修改集

6.3 规则生命周期

  • 编写：玩家在高级编辑器编写规则文本（或用模板库一键生成后修改）。
  • 编译：保存时编译器校验，错误则拒绝保存并提示修正。
  • 注入：编译后的字节码随战术存档存入数据库，比赛时注入 sim。
  • 求值：sim 每回合结束后按优先级顺序求值所有 enabled 规则。
  • 触发：条件满足则执行动作，进入冷却（如有）；maxTriggers 到达则禁用。

7条件表达式语法（BNF）

条件表达式支持 AND/OR/NOT 嵌套，比原 §6.1 的纯 AND 列表更灵活。以下为完整 BNF 文法。

7.1 条件表达式 BNF

ConditionExpr ::= OrExpr OrExpr ::= AndExpr ( "OR" AndExpr )* AndExpr ::= NotExpr ( "AND" NotExpr )* NotExpr ::= "NOT" NotExpr | Atom Atom ::= "(" OrExpr ")" | Condition Condition ::= CondType "." Field Op Value | CondType Op Value // 无字段简写 CondType ::= "score_diff" | "quarter" | "clock" | "clutch" | "has_ball" | "streak" | "team_fouls" | "opp_team_pts" | "player_fouls" | "player_condition" | "player_pts" | "player_on_court" | "opp_player_pts" | "timeouts_left" Op ::= "==" | "!=" | "<" | "<=" | ">" | ">=" Value ::= Number | Boolean | PlayerRef PlayerRef ::= "star1" | "star2" | "pg" | "sg" | "sf" | "pf" | "c" | "opp_star1" | "opp_star2" | PlayerId // 位置/角色/具体ID
AND 优先级高于 OR：与标准逻辑一致，A AND B OR C 等价于 (A AND B) OR C。用括号显式分组避免歧义。

7.2 条件类型完整表（扩展版）

CondType字段说明值域
score_diff—当前比分差（正=领先）-50~+50
quarter—当前节次1-9（5+=OT）
clock—当前节剩余秒数0-720（OT: 0-300）
clutch—是否 Clutch 时段true/false
has_ball—本方是否持球true/false

7.3 条件表达式示例

// 示例 1：第四节最后 5 分钟落后 8+ 分（纯 AND） score_diff <= -8 AND quarter >= 4 AND clock <= 300 // 示例 2：对方核心爆发 OR 对方全队高分（OR 嵌套） opp_player_pts.opp_star1 >= 20 OR opp_team_pts >= 60 // 示例 3：主力犯规麻烦 AND (节次早 OR Clutch 时段) player_fouls.star1 >= 4 AND (quarter <= 2 OR clutch == true) // 示例 4：NOT 嵌套——非 Clutch 时段且本方持球 NOT clutch == true AND has_ball == true // 示例 5：复杂组合——(落后且第四节) OR (Clutch 且领先不超过3) (score_diff <= -5 AND quarter >= 4) OR (clutch == true AND score_diff <= 3)

8动作表达式语法

动作表达式定义规则触发后对 sim 参数的修改。支持 set / multiply / add 三种操作，可引用 PlayerRef。

8.1 动作表达式 BNF

ActionList ::= Action ( "," Action )* Action ::= Param ActionOp ActionValue | SpecialAction ActionOp ::= "set" | "mul" | "add" // set=覆盖 mul=乘 add=加 ActionValue ::= Number | String | PlayerRef | TargetDefExpr Param ::= "tendencyMod[three]" | "tendencyMod[midrange]" | "tendencyMod[inside]" | "tendencyMod[drive]" | "tendencyMod[postup]" | "fastBreakChance" | "pickRollChance" | "defenseContest" | "defenseContest[three]" | "defenseContest[inside]" | "defenseContest[postup]" | "helpDefChance" | "stealChance" | "blockChance" | "possessionTime" | "conditionLossMul" | "foulStrategy" | "primaryScorer" | "rotationMode" | "matchupOverride" | "targetDef" | "threeFreq" SpecialAction ::= "substitute(" PlayerRef "," PlayerRef ")" // 换人 | "call_timeout()" // 叫暂停 | "set_role(" PlayerRef "," Role ")" // 改战术角色 TargetDefExpr ::= { type: "double_team"|"perimeter_lock"|"rim_protect"|"switch_all"|"hack_shaq", target: PlayerRef }

8.2 动作操作语义

操作语义适用参数示例
set覆盖为目标值枚举/引用型（foulStrategy, primaryScorer, targetDef）foulStrategy set "conservative"

add当前值 + 增量数值增量型（possessionTime）possessionTime add -3

所有动作执行后参数值受上下限钳制，防止规则叠加产出极端值：

11优先级与冲突解决算法

多条规则同时满足时，需确定参数修改集的最终值。以下为完整的冲突解决算法。

11.1 求值流程

// sim 每回合结束后执行 function evaluateRules(rules, gameState) -> ParamModSet { // STEP 1: 过滤——enabled 且未冷却且未达 maxTriggers active = rules.filter(r => r.enabled && !r.onCooldown && !r.maxedOut) // STEP 2: 求值——按 priority 降序检查条件 triggered = [] for r in active.sortByPriorityDesc() { if evalCondition(r.conditions, gameState) { triggered.push(r) r.enterCooldown() // 进入冷却 r.incrementTriggerCount() // 触发次数 +1 } } // STEP 3: 合并——按参数分组，解决冲突 return mergeActions(triggered.flatMap(r => r.actions)) }

11.2 冲突解决规则（完整版）

情况解决规则示例
不同参数叠加共存A 改三分倾向、B 改防守策略 → 两者同时生效
同参数不同 op按 op 类型顺序执行：先 set 再 mul 再 addA: set "aggressive" + B: mul 1.2 → 先 set 再 mul
同参数同 op（set）高 priority 覆盖低A(pri=50): set "normal" + B(pri=70): set "conservative" → "conservative"
同参数同 op（mul）倍率连乘（按 priority 降序）A(pri=70): mul 1.5 + B(pri=50): mul 1.3 → base × 1.5 × 1.3
同参数同 op（add）增量累加A: add -3 + B: add +2 → base + (-3) + 2
同 priority 同参数按规则列表顺序，后者覆盖（set）/累加（mul/add）列表中靠后的规则优先
最终钳制合并后值受 §8.3 值域钳制tendencyMod 连乘超 3.0 → 钳至 3.0
设计意图：mul 连乘而非覆盖——让多条"提升三分"规则可叠加（追分 + Clutch 同时触发时三分倾向更高），但受上限钳制防爆。set 覆盖——枚举型参数（犯规策略）只能有一个最终值，高优先级决定。

11.3 mergeActions 算法伪码

function mergeActions(actions) -> ParamModSet { // 按参数名分组 byParam = groupBy(actions, a => a.param) result = {} for (param, acts) in byParam { // 按 op 类型分桶：set / mul / add sets = acts.filter(a => a.op == "set").sortByPriorityDesc() muls = acts.filter(a => a.op == "mul").sortByPriorityDesc() adds = acts.filter(a => a.op == "add") val = baseValue(param) if sets.notEmpty() val = sets[0].value // 高 pri 覆盖 for m in muls val = val * m.value // 连乘 for a in adds val = val + a.value // 累加 result[param] = clamp(val, lowerBound(param), upperBound(param)) // 钳制 } return result }
