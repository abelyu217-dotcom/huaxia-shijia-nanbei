## 〇、原型战略定位

### 0.1 原型使命（一句话）

**用最小成本验证核心循环是否成立——在投入完整开发前，用一份30-60分钟的可玩Demo回答三个根本问题：**

```
Q1：玩家愿意"管一个家族"超过30分钟吗？
Q2：九品中正制+家族养成的核心玩法撑得起反复游玩吗？
Q3：魏晋南北朝的差异化定位玩家买单吗？
```

### 0.2 原型的三个核心价值

| 价值 | 内容 | 衡量标准 |
|------|------|---------|
| **验证价值** | 验证核心循环的成瘾性 | 30-60分钟内玩家愿意继续玩 |
| **融资价值** | 给投资人/合伙人看 | 5分钟路演能讲清楚核心卖点 |
| **决策价值** | 给开发团队明确方向 | 团队对"做什么/不做什么"有共识 |

### 0.3 原型不做的事（边界控制）

为了控制范围，原型**严格不包含**：

| 不做 | 原因 |
|------|------|
| ❌ 24个时代 | MVP聚焦东晋103年 |
| ❌ 200+家族 | 只做6个核心家族+10个NPC家族 |
| ❌ 完整经济系统 | 简化田庄为3-5种类型 |
| ❌ 完整战争系统 | 只做1个战役（淝水之战简版） |
| ❌ 完整美术 | 用极简美术/黑白线条即可 |
| ❌ 联机功能 | 纯单机原型 |
| ❌ 完整剧本 | 只做1-2个核心家族剧本片段 |

## 一、原型核心场景设计（5个核心场景）

### 场景A：家族建立（3分钟）

#### A1. 流程设计

```
[Step 1] 时代选择（30秒）
    └─ 仅显示1个选项：东晋（317年）
    └─ 时代背景CG：衣冠南渡（极简版）

[Step 2] 家族选择（1分钟）
    └─ 仅显示3个核心家族：
        - 琅琊王氏（守成路线）
        - 陈郡谢氏（武将路线）
        - 自建家族（自由路线）
    └─ 每个家族显示：家徽、代表人物、玩法简介

[Step 3] 族长与初始设置（1分钟）
    └─ 显示族长姓名（不可改）
    └─ 显示家族初始属性
    └─ 点击"开始"进入游戏

[Step 4] 开局大事件（30秒）
    └─ 衣冠南渡CG（极简版，2-3张图）
    └─ 玩家做出第一个选择：是否随司马睿南渡
    └─ 选择完成后进入主游戏
```

#### A2. 关键设计点

- **极简时代选择**：不显示24个时代选项，避免选择疲劳
- **家族选择简化**：只3个选项，新手不被淹没
- **快速进入游戏**：3分钟内必须开始第一回合
- **开局选择有意义**：南渡决策影响后续剧情

### 场景B：单回合核心循环（15-20分钟，玩家重复体验3-5轮）

#### B1. 单回合结构（春夏秋冬四季）

```
┌─ 春：养成与规划 ─────────────────────┐
│ • 查看族人列表                          │
│ • 选择1-2名族人培养                     │
│ • 经营田庄（简化版）                     │
│ • 召开家族会议（重要议题）               │
└────────────────────────────────────────┘
              ↓
┌─ 夏：外交与事件 ─────────────────────┐
│ • 处理外交事件                          │
│ • 联姻谈判（如果有合适对象）             │
│ • 应对突发随机事件                       │
└────────────────────────────────────────┘
              ↓
┌─ 秋：扩张与结算 ─────────────────────┐
│ • 秋收结算（田庄产出）                   │
│ • 招募部曲                              │
│ • 重要历史事件触发                       │
└────────────────────────────────────────┘
              ↓
┌─ 冬：年度总结 ────────────────────────┐
│ • 显示年度总结报告                      │
│ • 更新族谱                              │
│ • 进入下一年                            │
└────────────────────────────────────────┘
```

#### B2. 单回合时长设计

| 操作类型 | 玩家用时 | 系统反馈 |
|---------|---------|---------|
| 族人培养选择 | 30秒/族人 | 培养效果+1-3点属性 |
| 田庄经营 | 1分钟/季度 | 产出变化 |
| 家族会议 | 2分钟 | 决策影响政治资本 |
| 事件响应 | 1-2分钟/事件 | 事件结果影响家族属性 |

**单回合玩家总用时目标**：3-5分钟
**5回合玩家总用时**：15-25分钟
**完整原型总时长**：30-60分钟

#### B3. 单回合简化（原型版本）

**为了让原型聚焦核心循环，原型版本做以下简化**：

| 简化项 | 原型方案 | 简化理由 |
|--------|---------|---------|
| 族人属性 | 只保留4个属性（智力、武力、魅力、家世） | 避免UI过载 |
| 田庄 | 只保留1种田庄（自耕田） | 经济系统简化 |
| 部曲 | 不做（战役场景单独处理） | 战争系统独立 |
| 文化技能 | 只保留1个（清谈） | 核心机制验证 |
| 性格系统 | 简化为3轴（进取/仁慈/奢靡） | 决策简化为3轴 |
| 关系属性 | 只保留1个（与皇帝关系） | 聚焦政治核心 |

### 场景C：联姻决策（5分钟，体验1-2次）

#### C1. 流程设计

```
[Step 1] 系统提示：可联姻对象出现
    └─ 弹出"联姻机会"通知
    └─ 显示候选人：姓名、年龄、属性、家族、嫁妆

[Step 2] 玩家评估
    └─ 查看候选人详细信息
    └─ 与自家适龄族人匹配

[Step 3] 议亲决策
    └─ 选项A：联姻（具体家族）
    └─ 选项B：暂不联姻（继续观望）
    └─ 选项C：拒绝该候选人

[Step 4] 联姻谈判（简化）
    └─ 自动谈判结果（基于品级匹配）
    └─ 成功/失败反馈

[Step 5] 联姻结果
    └─ 双方家族关系变化
    └─ 后代预览（10年后出生）
    └─ 政治资本变化
```

#### C2. 关键设计点

- **简化谈判**：原型不模拟复杂谈判过程，直接给结果
- **后代预览**：让玩家直观看到联姻的"产出"
- **关系变化可视化**：用关系条直观显示

### 场景D：清谈品评（3分钟，体验1-2次）

#### D1. 流程设计

```
[Step 1] 清谈机会触发
    └─ 时间：东晋每年3-9月随机触发
    └─ 条件：玩家家族文化声望>50

[Step 2] 选择辩手
    └─ 玩家从族人列表选择1-2名辩手
    └─ 显示辩手属性：智力、清谈、玄学

[Step 3] 选择议题
    └─ 显示3-5个玄学议题
    └─ 玩家选择立场（正方/反方）

[Step 4] 辩论过程（极简）
    └─ 显示对方辩手
    └─ 显示双方属性对比
    └─ 玩家选择"重点发挥属性"

[Step 5] 结果判定
    └─ 显示胜率（基于属性对比）
    └─ 点击"开始辩论"
    └─ 显示结果：胜/负
    └─ 胜：文化声望+，可能结识新名士
    └─ 负：文化声望-，但有学习经验
```

#### D2. 关键设计点

- **极简辩论**：不模拟实际辩论文本，用属性对比+随机数判定
- **可视化对比**：用雷达图直观显示双方实力
- **结果有意义**：胜负都有收获，避免负反馈

---

### 场景E：关键事件触发——淝水之战简版（10分钟）

#### E1. 流程设计

```
[Step 1] 事件触发（前情）
    └─ 时间：383年（东晋太元八年）
    └─ 触发条件：玩家为陈郡谢氏或自建家族
    └─ 前情CG：前秦大军压境

[Step 2] 战略决策（5分钟）
    └─ 玩家选择战略：
        - 主动决战（高风险高回报）
        - 坚守不战（中等风险）
        - 求和（低风险低回报）
        - 利用情报（特殊选项）

[Step 3] 战役过程（极简）
    └─ 显示双方兵力
    └─ 显示谢玄指挥（如果玩家为谢氏）
    └─ 等待战役结果（系统判定）

[Step 4] 战役结果
    └─ 大胜：家族声望+30%，解锁北伐选项
    └─ 小败：家族声望-10%
    └─ 大败：家族降品风险

[Step 5] 战后处理
    └─ 玩家做出战后选择：
        - 接受封赏（声望+但可能遭猜忌）
        - 功成身退（避免猜忌）
        - 继续掌权（短期利益）
```

#### E2. 关键设计点

- **极简战役**：不做具体战术战斗，用判定系统模拟
- **多结局**：3种结局对应3种家族命运
- **决策有意义**：每个选择都有后果

## 二、原型技术选型

### 2.1 引擎选择对比

| 引擎 | 优势 | 劣势 | 原型推荐度 |
|------|------|------|-----------|
| **Godot 4** | 开源免费、轻量、UI系统优秀、2D性能好 | 国内生态弱、人才少 | ⭐⭐⭐⭐⭐ |
| **Unity 2D** | 工具链成熟、人才多、插件丰富 | 体积大、对小项目过重 | ⭐⭐⭐⭐ |
| **Unreal** | 顶级视觉 | 学习曲线陡、对2D不友好 | ⭐⭐ |
| **HTML5/Web** | 零安装、易于分享 | 性能差、不适合复杂逻辑 | ⭐⭐⭐ |
| **Ren'Py** | 适合文字冒险 | 不适合策略游戏 | ⭐ |

**强烈推荐**：**Godot 4**

理由：
1. **开源免费**：原型阶段0成本
2. **轻量级**：编译快，迭代快
3. **2D能力优秀**：本游戏主要是2D UI和卡片
4. **GDScript简单**：易学易用
5. **跨平台**：可一键发布Windows/Mac/Linux/Web

### 2.2 美术方案

**原型阶段美术定位**：**"低保真高质感"**

| 维度 | 方案 | 原因 |
|------|------|------|
| **角色** | 黑白线条画 + 少量水墨点缀 | 节省成本，聚焦玩法 |
| **场景** | 单色背景 + 关键元素水墨风 | 营造氛围但不耗成本 |
| **UI** | 简化UI + 古风字体 | 统一视觉调性 |
| **动画** | 极少动画，仅必要过场 | 节省时间 |

**具体方案**：
- 角色立绘：火柴人风格 + 黑白线条 + 服装标识
- 场景：单色背景 + 关键道具线稿
- UI：白底 + 行书字体 + 印章按钮
- 临时方案：用AI绘图工具生成场景氛围参考图

**美术资源清单**（原型最小集合）：
- 6个家族家徽（黑白线稿）
- 12个核心人物头像（黑白线稿）
- 5个场景背景（黑白线稿）
- 10个UI组件（黑白风格）
- 20个事件CG占位图（极简版）

### 2.3 数据架构**

```
核心数据表：
1. 家族表（family）
   - id, name, clan_id, rank（品级）, prestige（声望）, wealth（财富）
   
2. 族人表（character）
   - id, family_id, name, age, gender, intelligence, martial, charm
   - is_alive, position, traits
   
3. 关系表（relationship）
   - from_id, to_id, type, value
   
4. 事件表（event）
   - id, year, family_id, type, choices, results
   
5. 田庄表（estate）
   - id, family_id, type, output, level
```

**数据库选择**：
- **开发期**：JSON文件（简单、便于调试）
- **发布期**：SQLite（持久化、性能好）

### 2.4 技术风险清单

| 风险 | 等级 | 应对 |
|------|------|------|
| **时间轴系统复杂** | 🟡 中 | 简化时间粒度为"年"，季节作为标记 |
| **族谱数据结构** | 🟡 中 | 使用嵌套结构+扁平索引混合 |
| **AI家族行为** | 🟡 中 | 简化AI决策树，只做3-5种行为模式 |
| **存档兼容** | 🟢 低 | 原型阶段不做存档迁移 |
| **跨平台发布** | 🟢 低 | Godot天然支持跨平台 |

### 4.1 玩家操作树

```
主菜单
├─ 开始游戏
│  ├─ 选择时代（东晋）
│  ├─ 选择家族（3选1）
│  ├─ 家族建立
│  └─ 进入第一回合
│
├─ 主界面（家族面板）
│  ├─ 族人列表
│  │  ├─ 查看详情
│  │  ├─ 培养选择
│  │  ├─ 联姻安排
│  │  └─ 安排官职
│  ├─ 田庄经营
│  │  ├─ 查看田庄
│  │  ├─ 招佃户
│  │  └─ 调整经营
│  ├─ 家族会议
│  │  ├─ 提出议题
│  │  ├─ 族人投票
│  │  └─ 决策记录
│  ├─ 事件处理
│  │  ├─ 触发事件
│  │  ├─ 选择应对
│  │  └─ 查看结果
│  └─ 进入下季
│
└─ 退出/读档
```

### 4.2 系统响应规则

| 玩家操作 | 系统响应 | 反馈形式 |
|---------|---------|---------|
| 点击族人 | 弹出族人详情 | UI更新+音效 |
| 选择培养 | 培养进度更新 | 进度条+数值变化 |
| 选择议题 | 进入投票界面 | UI切换 |
| 选择事件选项 | 事件结果判定 | 弹窗+后续事件 |
| 进入下季 | 季度结算 | 总结报告+UI更新 |

### 4.3 自动化机制

为了减少玩家操作负担，原型版本**自动化处理以下内容**：

| 自动化内容 | 实现方式 |
|-----------|---------|
| 田庄日常经营 | 玩家只做季度关键决策，日常自动 |
| 族人日常培养 | 玩家只选方向，进度自动累积 |
| NPC家族行为 | 简化AI自动执行 |
| 时间推进 | 一键推进，无季节倒计时 |
| 事件触发判定 | 系统自动检测并通知玩家 |

## 六、原型验收标准

### 6.1 功能验收（必须100%通过）

| 验收项 | 验收标准 | 验证方式 |
|--------|---------|---------|
| **家族选择** | 3个家族可选择，每个有不同的开局状态 | 手动测试 |
| **族人培养** | 4个属性可培养，进度可视化 | 手动测试 |
| **田庄经营** | 季度结算正确，年产出符合预期 | 计算验证 |
| **联姻决策** | 联姻流程完整，后代属性符合算法 | 计算验证 |
| **清谈事件** | 辩论结果基于属性+随机数 | 计算验证 |
| **淝水之战** | 3种结局都可触发，结果影响家族属性 | 手动测试 |
| **存档读档** | 存档可读档，状态一致 | 手动测试 |

### 6.2 体验验收（核心团队主观评估）

| 评估项 | 评估标准 | 目标 |
|--------|---------|------|
| **上手难度** | 新玩家30分钟内能理解核心玩法 | ⭐⭐⭐⭐ |
| **核心循环** | 30-60分钟内玩家愿意继续玩 | ⭐⭐⭐⭐ |
| **沉浸感** | 玩家感到"在管一个真实家族" | ⭐⭐⭐⭐ |
| **策略深度** | 决策有意义，不是无脑点击 | ⭐⭐⭐ |
| **文化氛围** | 魏晋风度有体现 | ⭐⭐⭐ |

### 6.3 内部测试（10人小范围）

**测试场景**：
1. 邀请10人（5个游戏老手+5个历史爱好者）
2. 让每人玩30-60分钟
3. 收集反馈：愿意继续玩吗？哪些设计喜欢/不喜欢？

**通过标准**：
- ≥7人愿意继续玩（70%）
- ≥8人认为"核心玩法成立"（80%）
