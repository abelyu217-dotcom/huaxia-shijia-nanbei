## 〇、技术架构总览

### 0.1 架构目标

**构建一个稳定、可扩展、易维护、易扩展的家族养成策略游戏技术架构。**

五大核心目标：
1. **稳定可靠** —— 游戏运行不崩溃，存档不丢失
2. **可扩展** —— 支持从原型到完整版的迭代
3. **易维护** —— 模块化设计，新人能快速上手
4. **高性能** —— 在中端PC上流畅运行
5. **易发布** —— 一次开发多平台发布

### 0.2 五大架构原则

| 原则 | 核心 | 实现手段 |
|------|------|---------|
| **数据驱动** | 内容与逻辑分离 | JSON/YAML配置化 |
| **模块解耦** | 模块间低耦合 | 事件总线+接口隔离 |
| **单一职责** | 一个模块一件事 | 清晰的模块边界 |
| **渐进式实现** | 原型→完整版平滑过渡 | 关键模块优先 |
| **可观测性** | 可调试、可监控 | 日志系统+数据埋点 |

## 一、引擎选型深度分析

### 1.1 候选引擎对比矩阵

| 引擎 | 优势 | 劣势 | 适用度 | 推荐度 |
|------|------|------|--------|--------|
| **Godot 4** | 开源免费、轻量、2D优秀、GDScript简单 | 国内生态弱、人才少 | ⭐⭐⭐⭐⭐ | **首选** |
| **Unity 2D** | 工具链成熟、人才多、Asset Store丰富 | 体积大、对小项目过重 | ⭐⭐⭐⭐ | 备选 |
| **Unreal** | 顶级3D视觉 | 学习曲线陡、对2D不友好 | ⭐⭐ | 不推荐 |
| **GameMaker** | 2D友好、易上手 | 国内几乎无人用、生态弱 | ⭐⭐⭐ | 不推荐 |
| **Cocos2d-x** | 国内生态好、性能好 | 工具链老旧、文档少 | ⭐⭐⭐ | 不推荐 |
| **RPG Maker** | 上手快 | 限制大、扩展难 | ⭐⭐ | 不推荐 |

### 1.2 详细对比（重点引擎）

#### 1.2.1 Godot 4 vs Unity 2D

| 维度 | Godot 4 | Unity 2D | 评判 |
|------|---------|----------|------|
| **许可费用** | 完全免费（MIT协议） | 个人免费，企业版收费 | Godot胜 |
| **体积** | 几十MB | 几个GB | Godot胜 |
| **2D能力** | 原生2D节点系统 | 3D引擎附带2D | Godot胜 |
| **UI系统** | Control节点，简单直观 | UGUI/UI Toolkit | Godot胜 |
| **脚本语言** | GDScript/Python风格 | C# | 平手 |
| **性能** | 优秀（C++核心） | 优秀 | 平手 |
| **社区** | 国际社区活跃 | 国际化生态 | Unity胜 |
| **人才市场** | 招人难 | 招人容易 | Unity胜 |
| **Asset Store** | 资源少 | 资源多 | Unity胜 |
| **跨平台** | 全平台 | 全平台 | 平手 |
| **学习曲线** | 1-2周上手 | 1-3个月上手 | Godot胜 |

**结论**：**Godot 4更适合本项目**。理由：
1. 项目以2D为主，Godot的2D原生支持更优
2. 原型阶段资金有限，开源免费优势明显
3. 学习曲线短，团队快速上手
4. 跨平台发布方便

#### 1.2.2 Godot 4关键能力验证

| 能力需求 | Godot 4支持度 | 实现方式 |
|---------|--------------|---------|
| **2D UI渲染** | ⭐⭐⭐⭐⭐ | Control节点 + Theme |
| **事件系统** | ⭐⭐⭐⭐⭐ | Signal机制 |
| **数据持久化** | ⭐⭐⭐⭐ | SQLite + JSON |
| **存档系统** | ⭐⭐⭐⭐ | ResourceSaver + FileAccess |
| **脚本逻辑** | ⭐⭐⭐⭐⭐ | GDScript |
| **动画系统** | ⭐⭐⭐⭐⭐ | AnimationPlayer + Tween |
| **多语言** | ⭐⭐⭐⭐ | TranslationServer |
| **网络功能** | ⭐⭐⭐⭐ | WebSocket（暂不需要） |

### 1.3 引擎最终选型

#### 1.3.1 推荐方案：Godot 4.3+

```
核心选择：
- 引擎：Godot 4.3 LTS（长期支持版）
- 渲染：2D Forward+
- 脚本：GDScript（主）+ C#（性能关键模块）
- 数据：JSON（配置）+ SQLite（存档）

辅助工具：
- IDE：VSCode + Godot Tools插件
- 版本控制：Git
- 美术：Aseprite（2D精灵）+ Krita（插画）
- 打包：Godot Export Preset
```

#### 1.3.2 备选方案：Unity 2D

如果团队成员全是Unity背景，可以切换到Unity 2D，架构基本不变：
- 引擎：Unity 2022 LTS
- 渲染：URP 2D
- 脚本：C#
- 数据：ScriptableObject + JSON + SQLite
- UI：UI Toolkit（推荐）或 UGUI

### 2.2 核心数据表详细设计

#### 2.2.1 家族表（family）

```sql
CREATE TABLE family (
    id              INTEGER PRIMARY KEY,
    name            TEXT NOT NULL,           -- 家族名

    culture         INTEGER DEFAULT 0,       -- 文化声望
    politics        INTEGER DEFAULT 0,       -- 政治资本
    military        INTEGER DEFAULT 0,       -- 军事力量（部曲数）
    family_school   TEXT,                    -- 家学类型（书法/玄学/儒学等）
    family_style    TEXT,                    -- 家风（进取/守成/中立/隐逸）
    religion        TEXT,                    -- 宗教倾向（玄/佛/儒/道/混）
    location        TEXT,                    -- 所在地
    is_player       BOOLEAN DEFAULT 0,       -- 是否玩家家族
    is_alive        BOOLEAN DEFAULT 1,       -- 是否存续

    extinct_year    INTEGER,                 -- 消亡年份
    metadata        TEXT                     -- JSON扩展字段

```

```sql
CREATE TABLE character (

    skill_ruxue         INTEGER DEFAULT 0,   -- 儒学 0-100

    skill_calligraphy   INTEGER DEFAULT 0,   -- 书法 0-100
    skill_painting      INTEGER DEFAULT 0,   -- 绘画 0-100
    skill_music         INTEGER DEFAULT 0,   -- 音乐 0-100
    skill_chess         INTEGER DEFAULT 0,   -- 棋艺 0-100
    skill_medicine      INTEGER DEFAULT 0,   -- 医术 0-100
    skill_politics      INTEGER DEFAULT 0,   -- 政事 0-100
    skill_strategy      INTEGER DEFAULT 0,   -- 谋略 0-100
    skill_interpersonal INTEGER DEFAULT 0,   -- 人际 0-100

    skill_riding       INTEGER DEFAULT 0,    -- 骑射 0-100
    skill_command       INTEGER DEFAULT 0,   -- 统兵 0-100
    
    -- 性格属性（5轴）
    trait_aggressive    INTEGER DEFAULT 50,  -- 进取/守成 0-100
    trait_kind          INTEGER DEFAULT 50,  -- 仁慈/冷酷 0-100

    title               TEXT,                -- 官职

    -- 元数据

```

#### 2.2.3 关系表（relationship）

```sql
CREATE TABLE relationship (
    id              INTEGER PRIMARY KEY,
    from_char_id    INTEGER NOT NULL,
    to_char_id      INTEGER,
    to_family_id    INTEGER,
    type            TEXT NOT NULL,        -- 类型：family/marriage/master/ally/enemy
    subtype         TEXT,                -- 子类型：father/son/spouse/etc.
    value           INTEGER DEFAULT 0,    -- 关系值 -100~100
    year            INTEGER,              -- 关系确立年份
    metadata        TEXT,
    FOREIGN KEY (from_char_id) REFERENCES character(id)
);
```

#### 2.2.4 田庄表（estate）

```sql
CREATE TABLE estate (
    id              INTEGER PRIMARY KEY,
    family_id       INTEGER NOT NULL,
    type            TEXT NOT NULL,        -- 类型：自耕田/佃户田/园林/矿山等
    name            TEXT NOT NULL,
    level           INTEGER DEFAULT 1,    -- 等级
    output          INTEGER DEFAULT 0,    -- 年产出（两）
    workers         INTEGER DEFAULT 0,    -- 雇工数
    location        TEXT,
    created_year    INTEGER NOT NULL,
    metadata        TEXT,
    FOREIGN KEY (family_id) REFERENCES family(id)
);
```

#### 2.2.5 事件表（event）

```sql
CREATE TABLE event (
    id              INTEGER PRIMARY KEY,
    name            TEXT NOT NULL,
    year            INTEGER,              -- 发生年份
    season          TEXT,                -- 发生季节
    type            TEXT NOT NULL,        -- 类型：历史/随机/家族/战争/外交

    description     TEXT NOT NULL,
    choices         TEXT NOT NULL,        -- 选项（JSON数组）
    result          TEXT,                -- 结果（JSON）
    is_completed    BOOLEAN DEFAULT 0,
    metadata        TEXT
);
```

#### 2.2.6 存档表（savegame）

```sql
CREATE TABLE savegame (

    save_name       TEXT NOT NULL,
```

### 2.4 数据持久化方案

#### 2.4.1 存储分层

| 数据类型 | 存储位置 | 更新频率 | 备注 |
|---------|---------|---------|------|
| **配置数据** | JSON文件 | 启动时加载 | 只读 |
| **运行时数据** | 内存对象 | 每回合更新 | 高频 |
| **存档数据** | SQLite | 每回合保存 | 中频 |
| **日志数据** | 文件 | 实时追加 | 低频 |
| **埋点数据** | 本地+远程 | 实时 | 低频 |

#### 2.4.2 存档机制

```
存档触发时机：
1. 每个回合结束（自动）
2. 重要事件结束（自动）
3. 玩家手动存档（手动）

存档内容：
- 完整游戏状态（JSON序列化）
- 玩家家族状态
- 所有族人状态
- 关系网络
- 关键事件进度

存档压缩：
- LZ4压缩（速度快）
- 存档大小：1-5MB（单家族50年）
```

#### 2.4.3 数据迁移

由于游戏跨越369年，需要考虑数据迁移：
- **配置变更**：版本号机制 + 迁移函数
- **存档兼容**：旧存档自动迁移
- **数据校验**：存档加载时校验完整性

## 三、模块架构详细设计

### 3.1 模块拆分原则

**依据单一职责原则**，将游戏系统拆分为以下模块：

| 原则 | 含义 |
|------|------|
| **单一职责** | 一个模块只做一件事 |
| **接口隔离** | 模块间通过接口通信 |
| **依赖倒置** | 高层不依赖低层细节 |
| **开闭原则** | 对扩展开放，对修改关闭 |

### 3.2 核心模块清单

```
游戏系统
├── 1. 家族系统（Family System）
├── 2. 族人系统（Character System）
├── 3. 关系系统（Relationship System）
├── 4. 联姻系统（Marriage System）
├── 5. 文化系统（Culture System）
├── 6. 经济系统（Economy System）
├── 7. 军事系统（Military System）
├── 8. 政治系统（Politics System）
├── 9. 事件系统（Event System）
├── 10. AI系统（AI System）
├── 11. 时间轴系统（Timeline System）
├── 12. 存档系统（Save System）
└── 13. UI系统（UI System）
```

### 3.4 模块详细设计

#### 3.4.1 家族系统

**职责**：管理家族实例（创建、查询、修改、删除）

**核心接口**：

```gdscript
# family_manager.gd
class_name FamilyManager

# 创建家族
func create_family(config: FamilyConfig) -> Family

# 获取家族
func get_family(family_id: int) -> Family

# 更新属性
func update_family_attribute(family_id: int, attr: String, value: int) -> void

# 家族消亡判定
func check_extinction(family_id: int) -> bool

# 家族排行
func get_family_ranking(rank_type: String) -> Array
```

#### 3.4.2 族人系统

**职责**：管理族人实例、属性计算、培养逻辑

**核心接口**：

```gdscript
# character_manager.gd
class_name CharacterManager

# 创建族人
func create_character(template: CharacterTemplate, family_id: int) -> Character

# 培养族人
func train_character(char_id: int, skill: String, intensity: int) -> TrainingResult

# 计算属性成长
func calculate_growth(char_id: int) -> void

# 死亡判定
func check_death(char_id: int) -> bool

# 后代属性计算
func calculate_offspring(father_id: int, mother_id: int) -> CharacterTemplate
```

#### 3.4.3 关系系统

**职责**：管理人物之间、家族之间的关系

**核心接口**：

```gdscript
# relationship_manager.gd
class_name RelationshipManager

# 添加关系
func add_relationship(from_id: int, to_id: int, type: String, value: int) -> void

# 更新关系值
func update_relationship(rel_id: int, delta: int) -> void

# 查询关系
```

## 四、关键技术难点与解决方案

### 4.1 族谱系统

#### 4.1.1 技术难点

- **数据结构复杂**：父子、夫妻、兄弟姐妹、姻亲多维关系
- **跨代际管理**：369年跨度，可能涉及30+代
- **动态变化**：出生、死亡、婚配持续发生
- **查询性能**：复杂关系查询可能慢

#### 4.1.2 数据结构设计

```gdscript

func calculate_generation(char_id: int) -> int
```

### 4.2 时间轴系统

#### 4.2.1 技术难点

- **长跨度**：369年，可能跨30+代
- **细粒度**：季度、月份都可能触发事件
- **历史事件**：精确定位特定年份事件
- **性能**：时间推进不能卡顿

#### 4.2.2 时间推进架构

```gdscript
# game_time.gd
class_name GameTime

var year: int           # 当前年份

# 时间触发器
func on_season_change() -> Array
func on_year_change() -> Array
```

#### 4.2.3 性能优化

- **事件懒加载**：只加载即将触发的年份
- **历史快照**：每隔10年保存一个快照
- **索引优化**：用年表索引而非遍历

### 4.3 事件系统

#### 4.3.1 技术难点

- **事件数量**：可能200+核心事件+随机事件
- **触发条件**：复杂的复合条件
- **连锁反应**：一个事件触发多个后续事件
- **玩家影响**：玩家选择影响后续事件链

#### 4.3.2 事件架构


#### 4.3.3 事件链设计

```

    ↓

    ↓

    ↓
[玩家选择]
    ↓
[应用结果]
    ↓
[触发后续事件链] → 可能触发2-5个后续事件
```

### 4.4 AI家族系统

#### 4.4.1 技术难点

- **数量多**：20-30个NPC家族同时存在
- **决策复杂**：每个家族有自己的策略
- **玩家交互**：AI家族与玩家互动
- **动态变化**：家族命运随历史事件变化

#### 4.4.4 效用AI评分

```gdscript
# utility_evaluator.gd
class_name UtilityEvaluator

func evaluate_action(ai_family: AIFamily, action: AIAction) -> float:
    var score = 0.0
    
    # 个体属性评分（30%）
    score += ai_family.aggression * 0.3
    
    # 资源评分（30%）
    score += resource_score(ai_family, action) * 0.3
    
    # 关系评分（20%）
    score += relationship_score(ai_family, action) * 0.2
    
    # 历史评分（20%）
    score += historical_score(ai_family, action) * 0.2
    
    return score
```
