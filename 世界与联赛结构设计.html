世界与联赛结构设计 World & League Structure · HWO

本作作为多人在线游戏的"世界骨架"——决定玩家如何被组织、如何对抗、如何流动。每个世界是独立生态系统，自含联赛金字塔、共享球员池、独立经济与排名。世界之间不流通，保证公平与经济体量可控。本系统定义世界模型、联赛金字塔、全球时钟、赛程对阵、升降级、赛季交接、AI 经理填充、世界生成与扩容的完整规格。

1世界模型与数据结构

世界 = 一个独立生态系统。玩家注册时选择或被分配到一个世界。每个世界自含完整联赛金字塔、共享球员池（自由球员 + 选秀池 + 青训苗子池）、独立经济与排名。世界之间球员不流通（保证公平与经济体量可控）。

1.1 世界数据结构

World = { worldId: u16, // 世界唯一标识 name: string, // 世界名（如"东亚 01"） language: string, // 主语言（zh-CN / ja / ko 等） timezone: string, // 主时区（Asia/Shanghai 等） createdAt: Timestamp, currentSeason: u8, // 当前赛季序号 currentPhase: SeasonPhase, // 赛季阶段（见 §6） currentDay: u8, // 当前赛季日（1-180） // —— 联赛结构 —— pyramid: [League], // 联赛金字塔（§2） // —— 共享池 —— freeAgentPool: [PlayerId], // 自由球员池 draftPool: [PlayerId], // 选秀池（赛季末生成） youthAcademyPool: [PlayerId], // 青训苗子池 // —— 经济与排名 —— economy: WorldEconomy, // 世界级经济指标（经济系统 §9） ranking: [RankEntry], // 世界排名（三身份 §11） // —— 容量与状态 —— capacity: u16, // 最大球队数（256-512） activeTeams: u16, // 当前球队数（含 AI） humanManagers: u16, // 真人经理数 status: WorldStatus, // seeding | active | locked | merging }

1.2 世界容量与状态

状态说明准入
seeding新世界初始化中，生成 AI 球队/球员/赛程不可注册
active正常运营，接受新玩家注册可注册
locked容量接近上限，停止注册引导至新世界不可注册
merging低活跃世界合并（罕见，需官方运营触发）受限
  • 世界容量：每世界约 256–512 支球队（16 队/组 × 多组多级），随玩家增长开新世界。
  • 新世界触发：当现存世界 humanManagers / capacity > 80% 时，自动开新世界并引导新玩家。
  • 世界选择：按语言/时区/活跃度推荐；玩家可手动选择（但有冷却，见 §11）。

每个世界自含四级联赛金字塔，从顶级到入门级逐层扩容。升降级让球队在层级间流动，构成"流动的生态"而非"静态的分区"。

入门级弹性扩容：入门级组数随世界活跃度弹性调整（6-16 组），容纳新玩家涌入。高级别固定组数，保证稀缺性与竞争强度。新世界初期可仅开 T1-T3 + 少量 T4 组，随人口增长逐步开新 T4 组。

2.4 新经理起点分配

  • 默认：新注册经理分配到入门级某组 AI 球队，从底层开始攀登。
  • 付费选择：可付费（Credits）选择中游球队（T3-T4 中排名 6-12 的 AI 球队），跳过底层磨练。
  • 禁止顶级：不可付费选择顶级或次级球队，保护生态（防止人民币玩家直接入住豪门）。
  • 分配算法：优先分配到 humanManagers 最少的 T4 组，平衡各组人口。

3全球时钟与异步结算

所有世界同步：比赛结算、翻天、提交截止在同一全球节点进行。这保证选秀/自由市场/升降级跨世界同步，简化运营与版本管理。

3.1 每日时钟节点

09:30
提交截止
截止次日安排（阵容/战术/训练），过后该日不可改
10:00
比赛结算
所有世界同时 sim 当日全部对阵，产出 PBP/Box Score
16:00
翻天
资源/状态/球探报告翻页；Condition 恢复；新事件触发

3.2 时区适配

全球时钟以 UTC+8（亚洲/上海）为基准。各世界虽标注主时区，但结算节点统一按 UTC+8 执行，保证跨时区玩家同步体验。

世界主时区结算当地时区说明
Asia/Shanghai (UTC+8)10:00 当日标准基准，亚洲玩家主要时段
Asia/Tokyo (UTC+9)11:00 当日日本玩家
America/Los_Angeles (UTC-8)18:00 前日北美西海岸（跨日）
Europe/London (UTC+0)02:00 当日欧洲玩家（凌晨，少量世界）
设计取舍：本作主打亚洲市场（策划方案 §1.1），以 UTC+8 为基准最自然。非亚时区世界数量少，跨日结算对北美/欧洲玩家略有不便，但保证全球同步的运营简化收益大于时区便利损失。

3.3 结算流水线

// 每日 10:00 UTC+8 触发 function dailySettle(worlds) { for world in worlds.parallel() { // 所有世界并行结算 matches = world.getTodayMatches() for match in matches { result = simulateMatch(match) // Sim Engine 纯函数 applyResult(match, result) // 更新战绩/数据/Condition pushPBP(match, result) // 推送 PBP 给订阅者 } updateStandings(world) // 更新积分榜 checkMilestones(world) // 触发关键战/事件 } } // 每日 16:00 UTC+8 触发 function dailyFlip(worlds) { for world in worlds.parallel() { recoverCondition(world) // Condition 恢复 rollEvents(world) // 触发随机事件 refreshScoutReports(world) // 球探报告翻页 tickContracts(world) // 合同天数递减 } }

3.4 离线代管与补结算

  • 离线代管：玩家未在 09:30 截止前提交安排时，按上次存档 + AI 默认决策执行（战术系统 §14）。
  • 补结算：若结算时系统故障导致某世界未结算，在故障恢复后立即补结算，使用当日种子保证结果一致。
  • 不可回滚：结算结果一旦产出并推送，不可回滚（除非查实作弊，由仲裁人裁决）。

4赛程与对阵生成

4.1 赛程结构

每组 16 队，常规赛约 30 场/队，赛季约 60-70 天（每日 1 赛或隔日 1 赛）。

赛段对阵方式场次/队说明
组内主循环双循环（主客场各 1）30组内 15 队对手 × 2
跨组交叉同 tier 跨组单循环3-5增加对阵多样性
常规赛合计—~30约 60 天赛季
季后赛组内 top 8 单淘汰3-5BO1 / 决赛 BO3（§9）

4.2 赛程生成算法

function generateSchedule(league) -> [MatchDay] { teams = league.teams // 16 队 // 使用 Round-Robin Scheduling 生成双循环 rounds = circleMethod(teams) // 圆圈法，15 轮 × 2 (主客) // 插入跨组交叉赛（随机 3-5 场，分布均匀） crossOpps = pickCrossGroup(league, count=4) rounds = interleave(rounds, crossOpps) // 约束校验 assert(noThreeConsecutiveHome(rounds)) // 无连续 3 主场 assert(noThreeConsecutiveAway(rounds)) // 无连续 3 客场 assert(derbySpacing(rounds, league)) // 德比不背靠背 return assignDates(rounds, league.world.seasonStart) }
圆圈法 Round-Robin：固定 1 队，其余 15 队绕圆轮转，每轮配对。双循环 = 正向 15 轮 + 反向 15 轮（主客互换）。算法确定性强，保证赛程公平。

4.3 赛程约束规则

约束规则理由
连续主场/客场不超过连续 3 场避免赛程失衡
德比间距同城市德比至少间隔 10 场避免德比密集疲劳
背靠背同组背靠背不超过 2 次/季体力公平
赛季末最后 5 场不全是强队/弱队避免排名操纵
跨组交叉按上赛季排名配对（强对强、弱对弱）增加竞争性

4.4 对阵日分配

每组每日分配 8 场对阵（16 队 / 2）。赛季日历按"比赛日 - 休息日"交替编排：

  • 比赛日：当日有对阵的球队参赛，无对阵球队休息。
  • 休息日：Condition 恢复 + 训练 + 球探任务执行。
  • 全休日：每周 1 天全联赛休赛（如周日），用于世界事件/选秀/转会窗口。

5升降级系统

升降级让球队在金字塔层级间流动，是"流动生态"的核心驱动。赛季末按规则执行，构成晋升与降级的赌注。

5.1 升降级规则矩阵

层级升级名额降级名额规则说明
顶级联赛 T1—末 3 名降级无上级可升；末 3 名降入次级
次级联赛 T2各组前 2 升级末 3 名降级2 组 × 2 = 4 队升 T1；末 3 × 2 组 = 6 队降 T3
第三级 T3各组前 2 升级末 3 名降级4 组 × 2 = 8 队升 T2；末 3 × 4 组 = 12 队降 T4
入门级 T4各组前 2 升级—无下级可降；前 2 升 T3，保持向上流动
名额平衡：升降级名额严格配平——T1 降 3 = T2 升 3（另 1 队从 T2 冠军决赛产生占位补充）；T2 降 6 = T3 升 6；T3 降 12 = T4 升 12。确保金字塔容量稳定。

5.2 升降级判定流程

7AI 经理填充

未被人接管的球队由 AI 经理经营。AI 经理需拟真决策，保证世界初期竞争性与经济循环不断档。随真实玩家增加逐步替换 AI 球队。

7.1 AI 经理生成

  • 生成时机：世界 seeding 时批量生成 AI 球队；新赛季若 AI 球队降级产生的空位也由 AI 填充。
  • 能力分布：按金字塔层级分配 AI 球队实力——T1 球队平均 OVR 85+，T4 球队平均 OVR 65-70。保证升降级有"实力差"驱动。
  • 阵容生成：服务端按位置/能力/年龄分布生成虚构球员（策划方案 §5.4），无真实球员版权风险。
  • 性格倾向：每个 AI 经理有随机"性格"（保守/激进/培养型/赢在当下型），影响交易与轮换偏好。

7.2 AI 球队实力梯度

层级平均 OVR球星数薪资使用战术复杂度
T1 顶级85-922-3 名 90+接近工资帽/轻微超帽高级战术 + 条件规则
T2 次级78-851-2 名 85+工资帽 80-95%中级战术
T3 三级70-780-1 名 80+工资帽 60-80%基础战术
T4 入门62-700工资帽 40-60%基础战术

7.3 AI 经理替换

真人优先：当真人玩家申请接管某 AI 球队时，AI 经理被替换为真人。接管规则按 §2.4 新经理起点分配。优先替换 T4 球队，保护高级别 AI 球队的拟真竞争。
  • 替换顺序：T4 > T3 > T2 > T1（从底层替换，保高层 AI）。
  • AI 球队保护：T1 球队即使无人接管也保持 AI 经营，作为"boss 级"对手维持顶级竞争。
  • 玩家放弃球队：玩家离线超 1 赛季或主动放弃，球队转回 AI 经营。

8.2 世界扩容策略

触发条件扩容动作说明
humanManagers/capacity > 80%开新世界引导新玩家到新世界，避免老世界过载

8.3 世界合并（罕见）

世界合并是重度操作，仅在全世界持续低活跃时由官方运营触发。合并涉及球员池/经济/排名的重整，需谨慎处理球员去重与资产折算。默认不合并，宁可维持低活跃世界（AI 经理填充保证可玩性）。
  • 合并流程：选两个低活跃世界 → 球员池合并去重 → 球队按 OVR 重排入新金字塔 → 资产按比例折算 → 玩家迁移通知。
  • 玩家补偿：被合并世界玩家获 Credits 补偿 + 优先选球队权。

顶级联赛仅 1 组，组冠军即世界冠军。次级及以下每组独立季后赛，各组冠军独立。顶级联赛冠军获世界冠军戒指，是本作最高荣誉。

并非所有比赛同等重要。德比、升降级生死战、冠军战等关键战获高亮处理，进入"赛事快报"，影响 PBP 推送优先级与球迷事件。

10.2 赛事快报生成

关键战由 Sim Engine §17 赛事快报系统生成叙事文本，推送至全服或相关玩家。快报包含：比赛摘要 + 关键回合 PBP + 球员高光 + 叙事钩子（如"XX 终结 YY 的 12 连胜"）。

10.3 宿敌系统

宿敌动态生成：两队跨赛季累计对阵胜负差 ≤ 2 场时标记为"宿敌"。宿敌战触发额外叙事与球迷情绪，是长期叙事钩子的来源。宿敌关系跨赛季持续，直到胜负差拉开。

玩家可付费迁移世界（带球队/化身/职业人）。迁移受冷却与限制，避免经济套利。

12经济与排名的封闭性

世界内封闭：球员/货币/资源不跨世界流通。每个世界是独立经济体与排名池。封闭性是公平与经济体量可控的基础。

12.1 经济封闭性

  • 球员池封闭：自由球员/选秀池/青训苗子池均世界内封闭，不跨世界流通（经济系统 §1.4）。
  • 货币封闭：Credits 不跨世界转移（迁移携带上限 50% 折算，§11）。
  • 薪资空间封闭：各世界独立薪资空间池，工资帽按世界经济体量调校。
  • 天然通缩：赛季结算消耗 + 球员退役流出 > 新秀注入，经济有轻微通缩倾向，防止薪资空间无限膨胀（经济系统 §1.4）。

12.2 排名封闭性

  • 世界排名：三身份声望积分汇总（三身份 §11），世界内排名。
  • 跨世界不可比：不同世界经济体量/人口/赛季数不同，声望积分不跨世界比较。
  • 全服荣誉：冠军戒指/名人堂是跨世界可见的"荣誉"（非数值排名），允许全服展示。

12.3 跨世界共享的内容

内容是否跨世界说明
球员❌ 不共享各世界独立球员池
Credits❌ 不共享各世界独立经济
声望积分❌ 不共享各世界独立排名
冠军戒指✅ 全服展示荣誉性，无数值影响

13.3 AI 决策"聪明度"分级

AI 经理按层级有"聪明度"分级，高级别 AI 决策更优（战术系统 §14.2）：

  • T1 AI：高级战术 + 条件规则 + 精准交易评估（接近优秀真人经理）。
  • T2 AI：中级战术 + 合理交易评估。
  • T3-T4 AI：基础战术 + 简单交易评估（有明显可利用弱点）。
设计意图：AI 聪明度分级让低级别 AI 有"可利用弱点"，新手玩家能从 T4 升 T3 中获得成就感；高级别 AI 提供真正挑战，保证顶级联赛竞争强度。

14异常处理与边界情况

14.1 球队人数不足

  • 触发：球队因交易/伤病/退役导致可用球员 < 8 人（无法凑齐 5 首发 + 3 替补）。
  • 处理：系统从自由球员池自动签入最低 OVR 球员补足至 8 人（应急签约，薪资按底薪）。
  • 惩罚：连续 3 场人数不足，经理声望扣分（管理不善）。

14.2 经理长期离线

  • 1 赛季离线：球队由 AI 按上次存档代管（战术系统 §14）。
  • 2 赛季离线：标记"休眠"，球队进入接管池供新玩家申请接管。
  • 3 赛季离线：球队正式转回 AI 经营，原经理回归后需重新申请接管（按 §2.4 分配）。

14.3 升降级空位不平衡

  • 触发：因合并/扩容/球队放弃导致升降级名额不配平。
  • 处理：空位由 AI 球队填充（生成新 AI 球队补入目标层级）；多余名额递延至下季。

14.4 结算故障

  • 部分世界故障：故障世界标记"待结算"，恢复后补结算（用当日种子保证一致）。
  • 全服故障：回滚至故障前状态，修复后统一补结算，全服补偿 Credits。
  • 作弊查实：由仲裁人（三身份 §5.4）裁决，可回滚特定比赛结果。

14.5 赛季中途加入

  • 新玩家注册：赛季中途注册的玩家接管 T4 AI 球队，该队当季战绩保留（不重置），从加入日起按 AI 存档 + 玩家调整继续。
  • 公平性：新玩家不参与当季升降级（即使战绩够升级也保留原级），下季正常参与。避免赛季中途接管强队白嫖升级。
