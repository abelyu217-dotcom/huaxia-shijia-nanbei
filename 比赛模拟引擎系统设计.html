比赛模拟引擎系统设计 Sim Engine · HWO

篮球经理世界的比赛模拟引擎（Sim Engine）是整个游戏的核心引擎。它接收双方阵容、战术、球员状态作为输入，输出逐回合 PBP 直播、Box Score 统计、赛事快报叙事摘要。引擎为纯函数，输入相同则输出相同——可单测、可回放、可灰度调参、可防作弊。

1设计原则与架构

1.1 四大设计铁律

① 纯函数确定性
simulateMatch(inputs, seed) → result。相同输入永远产出相同结果。所有随机性来自种子驱动的 PRNG，无隐式状态、无系统时间、无 IO 副作用。
② 服务端权威
所有 sim 在服务端执行，客户端只读 PBP / Box Score / 快报。客户端零计算权威，从根源杜绝作弊。
③ 可回放可审计
每场比赛存档 (inputs_hash, seed)；任意历史比赛可 100% 精确复现。用于申诉仲裁、平衡回归、bug 复现。
④ 可灰度调参
所有数值常量抽离为配置表（sim_config.json），不停机热更新；A/B 对局用不同配置并行跑回归。

1.2 引擎输入

// 引擎主函数签名（伪代码） simulateMatch( homeRoster: Roster, // 主队 12 人名单 + 当前能力 + Condition + Traits awayRoster: Roster, // 客队同上 homeTactics: MatchTactics, // 战术设置（基础+高级+Clutch卡+半场调整+对位针对性） awayTactics: MatchTactics, homeChemistry: TeamChemistry, // 团队化学反应值（来自人际关系系统） awayChemistry: TeamChemistry, seed: u32, // 随机种子（由比赛ID哈希生成，确定性） config: SimConfig // 全局数值配置（可热更新） ) → MatchResult // Roster 数据结构 Roster = { players: Player[], // 12 人名单 starters: [5]playerId, // 首发五人 benchOrder: [7]playerId, // 替补顺序 } Player = { id, name, position, // PG/SG/SF/PF/C abilities: AbilitySet, // 20 项能力 1-99（服务端真实值） condition: f32, // 0-100 疲劳状态 traits: Trait[], // 特质标签（冷血杀手/玻璃人等） personality: Personality, // 性格（影响 AI 决策倾向） fouls: u8 = 0, // 本场个人犯规数 minutes: f32 = 0, // 本场已上场分钟数 stats: GameStats = 0, // 本场累计统计 }

1.3 引擎输出

MatchResult = { pbp: PBPEvent[], // 逐回合事件流（~100-110 条） boxScore: BoxScore, // 双方逐人统计 keyPlays: KeyPlay[], // 高光/关键回合索引 summary: MatchSummary, // 3-5 句叙事摘要 finalScore: (home: u16, away: u16), qScores: [(h, a); 4], // 四节比分（+OT） mvp: playerId, entropy: f32, // 比赛随机度指标（调试用） }

1.4 模拟层级架构

层级模块职责
L0PRNG & Seed确定性随机数生成；同一 seed 产出同一序列
L1Possession Loop回合循环：球权分配 → 决策 → 判定 → 球权转换
L2Decision Engine出手决策树：控球者选择 → 行动选择 → 出手类型
L3Resolution Engine投篮命中/失误/犯规/篮板/罚球的概率判定
L4Modifier LayerCondition/疲劳/化学/战术/Clutch 修正叠加
L5Rotation Engine换人决策：疲劳/犯规/对位/战术触发
L6Output LayerPBP 文本生成 + Box Score 汇总 + 快报叙事
架构约束：L0-L3 为纯计算层，不依赖外部状态；L4-L5 读取战术与状态但不修改原始输入（内部维护可变副本）；L6 仅消费 L1-L5 的输出。这样任何一层可独立单测。

2.2 能力归一化

所有能力在进入 sim 计算前先归一化到 0.0–1.0 区间，便于公式统一：

norm(ability) = clamp(ability / 99.0, 0.01, 1.0)

2.3 能力交互规则

单一能力不独立裁决，关键判定使用组合能力：

3回合结构与比赛流程

3.1 比赛时间模型

参数值说明
比赛总时长48 分钟（4 节 × 12 分钟）标准篮球比赛时长
模拟回合数~100-110 回合双方各约 50-55 个进攻回合
每回合耗时约 14-18 秒（均值 ~16s）含 24 秒进攻时限内的出手时间分布
加时赛5 分钟/OT，最多 3 OT第 4 OT 后强制 sudden death
每节节间2 分钟模拟间隔执行轮换检查、半场调整评估

3.2 单回合完整决策树

每个进攻回合经过以下完整流程。每个节点消耗一次或多次 PRNG 调用。

  • ① 球权归属判定跳球/进球后/死球后 → 确定进攻方
  • ② 进场与对位5 名进攻球员 vs 5 名防守球员，按战术对位规则匹配
  • ③ 控球者选择按战术角色（主控/副控）+ 能力 + 随机权重选控球者
  • ④ 攻击模式决策决策树：快攻？半场阵地？→ 控球者读取战术倾向
  • ⑤ 行动选择加权随机选择：投篮 / 传球 / 突破 / 背打
    • ⑤a 若传球选择接球者 → 传球判定（成功/被抢断）→ 新控球者 → 返回 ④
    • ⑤b 若突破突破判定（过人成功/被堵）→ 选择终结方式 → 进入 ⑥
    • ⑤c 若背打背打判定（到位/被顶出）→ 选择终结方式 → 进入 ⑥
    • ⑤d 若投篮直接进入 ⑥
  • ⑥ 出手类型与位置确定三分 / 中距离 / 内线 → 确定出手位置
  • ⑦ 防守反应判定对位防守者干扰 + 协防者干扰 → 防守修正
  • ⑧ 投篮命中判定baseRate + 能力加成 - 防守干扰 + 情境修正 + 随机
  • ⑨ 结果分支命中 / 未中 / 被盖帽 / 进攻犯规
    • ⑨a 命中计分 → 检查 and-one 罚球 → 球权转换
    • ⑨b 未中→ 进入 ⑩ 篮板争夺
    • ⑨c 被盖帽→ 进入 ⑩ 篮板争夺（或直接球权转换）
    • ⑨d 进攻犯规→ 失误 + 球权转换
  • ⑩ 篮板争夺所有球员按篮板争夺值加权竞争 → 进攻篮板 / 防守篮板
  • ⑪ 球权转换进攻篮板→返回④ / 防守篮板→对方球权 / 失误→对方球权
    • ⑪a 进攻篮板进攻方保留球权 → 重置进攻时钟 → 返回 ④
    • ⑪b 防守篮板防守方获得球权 → 进入快攻判定 → 对方回合 ①
  • ⑫ 回合结束更新双方球员统计、Condition 衰减、犯规检查 → 检查轮换 → 回合 +1

3.3 回合时间消耗模型

每个回合消耗的模拟时间决定比赛总回合数。时间消耗由进攻节奏和行动类型决定：

possessionTime = clamp( baseTime + tempoMod + actionTime + Random(-2, +2), 6, 24 ) baseTime = 16.0 // 秒，标准半场阵地战基线 tempoMod = 快攻倾向: -4.0 / 平衡: 0 / 慢节奏: +3.0 actionTime = { "three": -3.0, // 三分出手通常较快 "midrange": -1.0, "inside": +1.0, // 内线攻通常耗时更多 "drive": -2.0, // 突破较快 "postup": +3.0, // 背打耗时最多 "pass": +2.0, // 传球消耗额外时间 }
快攻判定：每回合开始时，若防守方刚获得球权（防守篮板/抢断/对方失误），执行快攻概率判定。快攻成功则跳过半场阵地决策树，直接进入简化终结判定（速度+控运为主，命中率修正更高）。

4.2 快攻判定

fastBreakChance = baseFB × ballHandlerSpeed × teamTempoMod × defenseRecoverMod baseFB = 0.15 // 防守篮板后基础快攻概率 baseFB (抢断后) = 0.35 // 抢断后快攻概率更高 ballHandlerSpeed = norm(Speed) × 0.6 + norm(Dribbling) × 0.4 teamTempoMod = 快: 1.4 / 平衡: 1.0 / 慢: 0.7 defenseRecoverMod = 1.0 - avg(defTeam.Speed) × 0.3 // 防守方速度越高快攻越难 // 快攻成功 → 简化终结判定（跳过半场决策树） // 快攻出手命中率 baseRate +10%（防守未落位）

4.3 控球者选择

半场阵地战中，每回合选择控球者。控球者通常是 PG，但战术角色可覆盖。

// 控球者权重 = 战术角色权重 × 能力适配 × Condition修正 × 随机 ballHandlerWeight[p] = roleWeight[p] × abilityFit[p] × condMod[p] roleWeight: 主控（Primary Handler） = 3.0 副控（Secondary） = 1.0 其他 = 0.15 // 偶尔由非控球者发起 abilityFit[p] = 0.4×norm(Dribbling) + 0.3×norm(Passing) + 0.2×norm(OffIQ) + 0.1×norm(Speed) // 战术可指定特定球员为固定主控（如"以核心后卫为轴"）

4.4 传球链

控球者可选择传球而非直接攻击。传球链模拟球的流动：

  • 传球次数上限：单回合最多 4 次传球（第 5 次强制出手，模拟进攻时限压力）
  • 每次传球：消耗 ~3-5 秒模拟时间 + 一次传球成功/失误判定
  • 传球目标选择：按战术角色（主攻点/空位射手/内线枢纽）+ 空间位置加权
  • 传球失误概率：由传球者 Passing + 接球者 OffIQ + 防守者 Steal 决定
passTurnoverChance = 0.04 × (1 - norm(Passing)×0.5) × (1 + norm(nearestDefSteal)×0.6) // 基础 4% 失误率，好传球者降至 ~2%，面对抢断高手升至 ~6%

5出手决策算法

出手决策是 sim engine 的核心：每回合从多种行动中加权随机选择一种。权重由球员能力 × 战术倾向 × 对位 × 情境共同决定。

5.3 完整权重计算

// 对球员 p 在当前情境下，每种行动的权重 actionWeight[p][action] = baseWeight[action] × abilityMod[p][action] // 球员能力修正 × tendencyMod[action] // 战术倾向修正 × matchupMod[p][action] // 对位修正 × situationMod[action] // 情境修正（比分/时间/疲劳） × personalityMod[p][action] // 性格修正 × clutchMod[action] // Clutch 覆盖（仅最后3分钟/OT） // 最终概率 = 归一化后的权重 actionProb[p][action] = actionWeight[p][action] / Σ(actionWeight[p][*])

5.3.1 能力修正 abilityMod

abilityMod[three] = norm(ThreePoint) × 1.5 + 0.3 abilityMod[midrange]= norm(MidRange) × 1.5 + 0.3 abilityMod[inside] = (norm(Inside)×0.6 + norm(Strength)×0.4) × 1.5 + 0.3 abilityMod[drive] = (norm(Dribbling)×0.4 + norm(Speed)×0.35 + norm(Agility)×0.25) × 1.5 + 0.2 abilityMod[postup] = (norm(PostMove)×0.5 + norm(Strength)×0.3 + norm(Inside)×0.2) × 1.5 + 0.2 abilityMod[pass] = (norm(Passing)×0.5 + norm(OffIQ)×0.5) × 1.2 + 0.4 // 球员风格（终结型/3D/组织型等）作为额外乘数 // 如"组织型" pass ×1.3, drive ×0.8 // 如"终结型" inside ×1.2, drive ×1.1, pass ×0.8

5.3.2 对位修正 matchupMod

对位修正让球员根据防守者的强弱调整出手选择——"聪明地攻击弱点"。

// 三分出手对位修正：对手外线防守越强，三分意愿越低 matchupMod[three] = clamp(1.5 - norm(defPerimeterD)×0.8, 0.4, 1.5) // 内线出手对位修正：对手内线防守越强，攻筐意愿越低 matchupMod[inside] = clamp(1.5 - norm(defInteriorD)×0.7 - norm(defStandingReach)×0.2, 0.3, 1.5) // 突破对位修正：对手横移防守越差越愿突破 matchupMod[drive] = clamp(0.5 + (1-norm(defPerimeterD))×0.8, 0.3, 1.8) // 背打对位修正：对手力量越弱越愿背打 matchupMod[postup] = clamp(0.5 + (1-norm(defStrength))×0.8, 0.3, 1.6)

6.4 防守干扰 defensePenalty

防守干扰由对位防守者 + 协防者共同构成。干扰程度分为"空位 / 轻微干扰 / 强干扰 / 严密防守"四档。

// 防守干扰度 = 对位防守者干扰 + 协防者干扰 defenseContest = clamp( primaryDefContest × 0.75 + helpDefContest × 0.25, 0.0, 1.0 ) // 对位防守者干扰（使用 §2.3 的防守组合能力） primaryDefContest[three, midrange] = defQuality[perimeter] // 外线防守组合 primaryDefContest[inside, drive, postup] = defQuality[interior] // 内线防守组合 // 协防触发判定 helpDefContest = 0 // 默认无协防 if RNG() < helpDefChance: helpDefContest = helpDefQuality × 0.6 // 协防干扰折扣 helpDefChance = 0.20 × norm(nearestHelpDefIQ) // 高 DefIQ 球员更易协防 // defensePenalty = 干扰度 × 出手类型干扰系数 defensePenalty = defenseContest × contestImpact[shotType] contestImpact: three: 0.12 // 三分受干扰影响大 midrange: 0.10 inside: 0.14 // 内线受护筐影响最大 drive: 0.13 postup: 0.08 // 背打受干扰影响相对小（已卡住位置）
干扰档位与 baseRate 选择：defenseContest < 0.2 → 空位（使用空位 baseRate）；0.2-0.5 → 轻微干扰；0.5-0.75 → 强干扰；> 0.75 → 严密防守（使用受干扰 baseRate）。四档之间线性插值，避免硬切换。

7防守对位算法

7.1 对位匹配规则

每回合开始时，防守方 5 人按以下规则匹配进攻方 5 人：

  1. 默认对位：PG↔PG, SG↔SG, SF↔SF, PF↔PF, C↔C（按注册位置）
  2. 战术对位覆盖：战术可指定针对性对位（如"用最好的外线防守者锁对方核心 SG"）
  3. 换防：挡拆后自动换防（见 7.3），换防后对位临时变更
  4. 对位针对性策略：策划方案 §8.3 的 4 种针对性防守（包夹/护筐/换防/放投）

7.2 对位针对性策略

策略触发Sim 效果
包夹（Double Team）对方核心持球时defenseContest +0.2 但 passTurnoverChance ×0.5（更容易传球出空位）；被包夹者 turnoverChance ×1.5
护筐（Protect the Rim）对方攻筐时inside/drive 的 defensePenalty ×1.3 但 three 的 defensePenalty ×0.6（放投外线）
换防（Switch All）挡拆时消除挡拆错位优势 但 matchupMod 重算（可能形成小打大/大打小）
放投（Sag Off）对方三分差时three 的 defensePenalty ×0.4 但 drive 的 defensePenalty ×1.2（收缩防守堵突破）

7.4 协防系统

8篮板争夺算法

8.1 篮板争夺模型

投篮未中后，所有场上 10 名球员参与篮板争夺。每个球员有一个篮板争夺值，按权重分配球权。

// 每个球员的篮板争夺值 reboundContest[p] = reboundQuality[p] × positionMod[p] × condMod[p] × Random(0.7, 1.3) // reboundQuality 使用 §2.3 的篮板组合公式 // positionMod: C=1.5, PF=1.2, SF=0.8, SG=0.5, PG=0.4（位置篮板优势） // condMod: Condition 100=1.0, 50=0.85, 30=0.70 // 前场篮板 vs 后场篮板的分配 orebChance = Σ(offTeam.reboundContest) / Σ(all.reboundContest) × orebBaseMod orebBaseMod = 0.72 // 防守篮板天然优势（约 72% 防守篮板） // 实际 OREB% ≈ 28%（NBA 平均约 25-30%）

8.2 篮板归属判定

// 在获得篮板方内部分配给具体球员 rebounderProb[p] = reboundContest[p] / Σ(reboundingTeam.reboundContest) // 特殊：长篮板（三分未中弹远）→ 后卫参与度提升 if shotType == "three" && RNG() < 0.3: positionMod[PG, SG] = 0.9 // 30% 三分未中为长篮板，后卫可争 positionMod[C] = 1.2 positionMod[PF] = 1.1

18纯函数与种子系统

18.1 PRNG 选择

使用 mulberry32 算法作为 PRNG：速度快、周期足够、确定性强、无状态依赖。

// mulberry32 伪代码 mulberry32(seed) { state = seed return function() { state |= 0; state = state + 0x6D2B79F5 | 0 t = Math.imul(state ^ state >>> 15, 1 | state) t = t + Math.imul(t ^ t >>> 7, 61 | t) return ((t ^ t >>> 14) >>> 0) / 4294967296 } }

18.2 种子生成规则

seed = hash(matchId + "_" + seasonId + "_" + dayIndex) // matchId = 全局唯一比赛ID（含世界ID+联赛ID+赛季+场次） // 同一场比赛永远使用同一 seed → 永远可复现 // seed 写入 MatchResult 存档，用于回放与审计
