System Design · Scouting

球探系统 Scouting System

球员获取链路的信息引擎。用"迷雾（fog）—预算—任务—报告"四要素，把"签约/选秀/青训淘苗"从无脑点选变成有风险的信息博弈。球探不是"看了就准"的透视眼，而是投入预算、消耗时间、按等级与专长产出不确定收窄的侦察行动。球探职业人（三身份）与球探系统深度耦合，构成去中心化的情报供给侧。

1设计原则

核心定位：球探系统是球员获取链路的"信息引擎"。它不直接产出球员，而是产出关于球员的不确定信息（迷雾收窄报告），让签约/选秀/青训淘苗成为"基于不完全信息的博弈"，而非"看数值点选"。
① 信息即风险 核心
所有未探查球员的能力/ Peak 都是带 ±误差的估值。球探报告收窄误差区间，但永远无法精确到真实值（除非对阵亲历）。签约=赌 fog 内某点。
② 预算即稀缺 约束
球探预算有限，探查高层级赛事/远距离目标更贵。经理必须在"广撒网"与"深挖重点"间分配。
③ 时间即成本 博弈
球探任务耗时（1-7 日），派出后不可中途改任务。机会成本：探 A 就探不了 B。
④ 职业人即供给侧 经济
球探是三身份中的职业人之一。玩家可自任球探为他队服务赚薪，也可雇佣他人球探。去中心化情报市场。

1.1 不做什么

  • 不做透视眼：球探报告永远收窄 fog 但不消除 fog。真实 Peak/能力只有服务端知道，签约前永远有不确定性。
  • 不做免费情报：所有探查消耗预算与时间。无"自动全可见"模式（除对阵亲历的有限收窄）。
  • 不做永久准确：报告有时效，球员能力变化后旧报告衰减（§15）。球探是持续投入，非一劳永逸。
  • 不做跨世界探查：球探只能探查本世界内球员池（世界结构 §3 球员池封闭原则）。

2系统总览与架构

2.1 球探系统在球员获取链路中的位置

世界生成球员池
（FA/选秀/青训） → 球探探查
（消耗预算+时间） → 迷雾收窄报告
（±误差区间） → 经理决策
（签约/选秀/淘苗） → 真实值揭晓
（签约后/对阵后）

球探系统是"球员池→经理决策"之间的信息过滤层。没有球探，经理看到的只是粗估 ±20 的大 fog；球探投入越多，fog 越窄，决策风险越低，但预算与时间有限。

2.2 四层架构

层名称职责
L1任务层 Task Layer经理指派球探任务（目标球员/赛事层级/任务类型）；球探职业人接受雇佣
L2结算层 Settlement Layer任务到期结算：roll 收窄幅度、生成 ScoutReport、扣预算、扣球探体力。纯函数 + 确定性 PRNG
L3报告层 Report LayerScoutReport 存档、衰减、叠加；Watchlist 自动跟踪
L4揭晓层 Reveal Layer签约/选秀/对阵亲历时，按规则揭晓真实值并校验历史报告准确度

2.3 核心数据结构

── 球探任务（经理指派） ── ScoutTask = { taskId: u64, teamId: TeamId, scoutId: ProHandleId, // 球探职业人（自雇或雇佣） taskType: ScoutTaskType, // 球员探查/赛事现场/区域扫描/跟踪确认 target: ScoutTarget, // 目标球员/赛事层级/地理区域 budgetCost: u32, // 预算消耗 duration: u8, // 任务日数 1-7 startDay: u8, 赛季日 status: "running" | "done" | "aborted", } ── 球探报告（任务结算产出） ── ScoutReport = { reportId: u64, teamId: TeamId, playerId: PlayerId, scoutId: ProHandleId, generatedDay:u8, abilityFog: Map<AbilityKey, (est, range)>, // 各能力估值与±区间 peakFog: (est, range), // Peak 估值与区间 traitHints: [TraitHint], // 特质线索（可能不全/不准） narrative: string, // 球探评语叙事 confidence: f32, // 报告置信度 0-1 freshness: f32, // 新鲜度 1.0→衰减（§15） }

3迷雾 fog 系统

fog 是球探系统的核心机制——所有未签约球员的能力与 Peak 对经理呈现为带 ±误差的估值区间，而非真实值。

3.1 fog 的来源

来源初始 fog说明
世界生成±20（全能力）球员生成时 fog 基线。任何经理第一次看到都是 ±20
赛事可见度±15 ~ ±8球员参加高层级赛事后，所有经理的基础 fog 自动收窄（成长线 §5 球探可见度）
球探报告按等级收窄主动探查的主要收窄途径
Watchlist缓慢自动收窄长期跟踪的被动收窄（§8）
对阵亲历±3交手后对该球员的有限收窄（§13）

3.2 fog 的可视化

经理在球员卡片上看到的不是单一数值，而是估值 ± 区间的条形：

三分 ThreePT
68 ±20（未探）
三分 ThreePT
68 ±12（1次探）
三分 ThreePT
68 ±6（3次探）

金色竖线为估值点（est），色带为 ±区间。区间越窄，色带越绿越窄。经理永远不知道真实值在区间内何处。

3.3 fog 收窄计算

── 单次球探任务的 fog 收窄 ── fogNarrow = baseNarrow(targetAge) + skillRoll(scouting) * 0.6 + scoutLevel * 0.4 - distancePenalty - tournamentLevelPenalty // baseNarrow 按年龄（年轻苗子更难看清） baseNarrow(age): 8-12 → 2.0 // 童子期：潜力远，难看清 13-15 → 3.0 // 少年期：逐渐清晰 16-18 → 4.0 // 青年期：接近选秀，较清晰 19-25 → 5.0 // 成人期：数据样本足，最清晰 26+ → 4.5 // 老将：衰退轨迹有不确定性 // 收窄后新 fog newFog = max(fogFloor, currentFog - fogNarrow) // fogFloor = 2（永远保留 ±2 不可消除，除非对阵亲历）

3.4 fog 的不对称性

设计要点：fog 收窄是"双向收窄"——区间从两端同时缩小，估值点（est）可能微移但不会跳变。这避免"探了反而更糊涂"。但 Peak 的 fog 比能力 fog 更难收窄（Peak 隐藏更深），需要专项"潜力探查"任务（§4）且 fogFloor 更高（±5）。这让"赌天花板"永远是高风险决策。

4球探任务体系

4.1 四大任务类型

任务类型目标产出耗时预算
球员探查

潜力探查

赛事现场

4.2 任务详情：球员探查

  • 目标：经理指定 1 名已知球员（青训预备名单/选秀池/自由球员池/对手名单）。
  • 产出：该球员全部能力 fog 各收窄 fogNarrow；30% 概率获得 1 条特质线索（TraitHint）。
  • 耗时：2-3 日（取决于距离）。
  • 预算：基础 50 + 距离系数。
  • 限制：同一球员 7 日内重复探查收益递减（每次 fogNarrow ×0.7）。

4.3 任务详情：潜力探查

  • 目标：指定 1 名球员，专攻 Peak fog。
  • 产出：Peak fog 收窄（baseNarrow ×0.6，且 fogFloor = ±5 而非 ±2）。
  • 耗时：3-5 日（比球员探查久）。
  • 预算：基础 80 + 距离系数。
  • 设计意图：Peak 是最关键也最隐藏的信息。潜力探查是"赌天花板"流派的必备投入，但即便多次探查也无法消除 ±5 的核心不确定性。

4.4 任务详情：赛事现场

  • 目标：指定业余金字塔赛事层级（成长线 §5：城市/省/国家/洲际/国际）。
  • 产出：该赛事所有参赛苗子 fog 各收窄 fogNarrow ×0.4（广撒网，单兵收窄弱）；有概率发现新苗子加入预备名单。
  • 耗时：5-7 日（覆盖整个赛事周期）。
  • 预算：高层级赛事更贵（城市 80 → 国际 300）。
  • 发现新苗子：赛事现场有概率发现原本不在预备名单的苗子，加入后可后续深探。

4.5 任务详情：区域扫描

  • 目标：指定地理区域（如"华东区""华南区"）。
  • 产出：区域内 3-8 名未知苗子发现 + 粗略 fog（±15）；不深探单个。
  • 耗时：5-7 日。
  • 预算：基础 120。
  • 用途：赛季初广撒网发现淘苗目标，再针对重点苗子深探。

5球探报告

5.1 报告内容

每次球探任务结算产出一份 ScoutReport，包含：

字段说明
abilityFog各能力的 (est, range) 估值区间。球员探查产出全能力；赛事现场仅产出部分能力
peakFogPeak 的 (est, range)。仅潜力探查产出；其他任务不更新 Peak fog
traitHints特质线索列表。每条线索有置信度（30%-80%），可能存在误报
narrative球探评语叙事（如"投射手感柔和但防守端横移偏慢"），定性补充
confidence报告整体置信度 0-1。受球探等级、任务类型、距离影响
freshness新鲜度 1.0 起步，随时间衰减（§15）

5.2 报告叠加规则

同一球员被多次探查时，报告叠加而非覆盖——取各报告收窄后的最窄区间，但 est 加权平均：

── 多报告叠加 ── mergedRange = min(allReports.range) // 取最窄 mergedEst = weightedAvg(allReports.est, confidence) // 按置信度加权 mergedConfidence = 1 - product(1-r.confidence for r in allReports) // 置信度叠加 // 但 Peak fog 不叠加收窄——每次潜力探查独立收窄，取最窄 // 且 Peak 的 fogFloor = ±5 永远保留

5.3 特质线索 TraitHint

特质线索是不确定的——球探可能看错：

线索置信度含义误报率
80%球探很确定20% 可能是错的
50%球探有印象50% 可能是错的
30%球探隐约觉得70% 可能是错的
设计意图：特质线索让球探报告不只是数字区间，还有"软情报"。但软情报有误报率——经理需判断哪些线索可信。特质揭晓（成长线 §4.2）在赛事中触发，揭晓后校验历史 traitHint 准确度，反馈给球探职业声望。

5.4 球探评语叙事

评语基于 fog 数据生成定性描述，增添沉浸感与决策线索：

高 fog 收窄+高置信
"投射能力已确认属上乘，三分估值 72±4，可放心培养"
Peak fog 仍宽
"潜力上限仍有较大不确定性（±8），建议继续跟踪或谨慎评估"
特质线索低置信
"球探隐约察觉该球员有大心脏特质，但样本不足，需更多观察"
衰退轨迹苗子
"26 岁但速度 fog 下沿偏低，需警惕早期衰退"

6球探预算

6.1 预算来源

来源量级说明
球队基础预算300/赛季每赛季初分配，所有球队均有
世界等级加成+100~300T1 球队球探预算更高（世界结构 §8）
经理声望加成+50~200高声望经理获得额外球探资源
专项投入灵活经理可从总预算中额外拨给球探（经济系统）

6.2 预算消耗

── 任务预算消耗 ── budgetCost = baseCost[taskType] * distanceMod // 距离系数 1.0-2.0 * tournamentMod // 高层级赛事更贵 1.0-3.0 + scoutSalary // 雇佣球探的当日薪资（自雇则免） // baseCost 球员探查: 50 潜力探查: 80 赛事现场: 80(城市) ~ 300(国际) 区域扫描: 120

6.3 预算管理策略

预算稀缺性：一个赛季总预算约 500-800，而一次国际赛事现场就要 300。经理必须在"广撒网发现苗子"与"深挖重点目标"间分配。选秀前集中投入探查顺位目标，日常保留少量预算跟踪自家青训苗子。预算不可透支。

7球探职业人与雇佣

7.1 球探的三个技能分支

7.4 球探声望反馈

球探报告的准确度反哺球探职业声望（三身份 §11）：

  • 报告准确（揭晓后真实值落在 fog 区间内）：职业声望 +5/份。
  • 报告失准（真实值落在 fog 区间外）：职业声望 -3/份。
  • 特质线索正确：声望 +10/条。
  • 特质线索误报：声望 -5/条。
  • 声望影响球探可应聘的高级岗位与雇佣薪资。

8Watchlist 长期跟踪

Watchlist 是被动跟踪机制——将球员加入关注名单后，系统自动缓慢收窄 fog，无需主动派任务。

8.1 Watchlist 机制

── Watchlist 自动收窄 ── // 每日 16:00 翻天时结算 if (player in team.watchlist): autoNarrow = 0.5 * scoutLevelMod // 取决于队内球探等级 player.fog = max(fogFloor, player.fog - autoNarrow) // Watchlist 容量限制 watchlistCap = 20 + scoutLevel * 5 // 球探等级越高，可跟踪越多

8.2 Watchlist vs 主动探查

维度Watchlist主动探查
收窄速度慢（0.5/日）快（2-5/任务）
预算消耗0有
时间消耗0（后台自动）占用球探 2-7 日
覆盖广度可达 20-50 人单次 1 人/1 赛事
特质线索无有概率
Peak fog不收窄潜力探查可收窄
策略组合：Watchlist 适合"长期观察多个潜力股"，主动探查适合"选秀/签约前对重点目标深挖"。成熟经理会先用 Watchlist 广撒网，再用主动探查集中火力。

9探针系统

探针是球探系统的"高精度工具"——消耗稀缺资源换取单次高精度收窄。

9.1 探针类型

探针效果获取限制
试训邀请邀请球员来队试训 1 日，全能力 fog 一次性收窄 ±6消耗预算 100 + 球员好感仅自由球员/选秀前；球员可拒绝
医疗体检体检报告：Durability 真实值 ±2、伤病隐患线索消耗预算 150 + 医疗组等级≥3仅签约前；球员须同意
心理评估MentalFortitude / ClutchIQ 真实值 ±3、心理特质线索消耗预算 120 + 心理咨询师签约/选秀前
数据挖掘挖掘球员历史赛事数据，收窄已衰退老将的轨迹 fog消耗预算 80 + 情报网络技能仅 26+ 老将

9.2 探针的特殊性

  • 探针可触及 fogFloor 以下：试训/体检/心理评估的收窄可突破 ±2 的常规 fogFloor，最低至 ±1。这是探针的核心价值。
  • 探针不可重复：同一球员同种探针仅可使用 1 次（避免无限刷精度）。
  • 探针需球员同意：试训/体检/心理评估需球员好感达标或合同条款配合，不可强制。
  • 选秀前窗口：选秀前 7 日开放"联合试训"探针窗口，所有选秀池球员可集体浅探（fog 各收窄 ±3）。

10青训淘苗

青训淘苗是球探系统在青训苗子池（youthAcademyPool）的应用——发现 8-12 岁童子期苗子并纳入青训体系。

10.1 淘苗流程

区域扫描/赛事现场 → 发现未知苗子
（粗略 fog ±15） → 球员探查深挖
（收窄 fog） → 潜力探查 Peak → 纳入青训预备名单 → 青训学院培养

10.2 淘苗的特殊性

  • 童子期 fog 最宽：8-12 岁苗子 baseNarrow 仅 2.0，且初始 fog ±20。看清童子期苗子最难。
  • Peak fog 尤甚：童子期潜力探查 fogFloor = ±8（比成人 ±5 更宽）。赌童子期天花板是最高风险决策。
  • 苗子竞争：高质量苗子（S/A 档）会被多队球探发现，纳入预备名单有竞争——先到先得或好感竞争。
  • 错过窗口惩罚：童子期未纳入青训体系的苗子，Trainability 上限锁定 0.7（成长线 §4.1）。球探发现后不纳入=浪费。

10.3 淘苗决策博弈

核心博弈：童子期 fog 极宽，经理是"花大量预算深探一个 ±15 的苗子"，还是"广撒网浅探多个 ±18 的苗子"再择优深探？前者赌单个天花板，后者分散风险但每个都不够清。这是青训流建队的核心决策循环。

11选秀探查

选秀是球探投入的高峰期——选秀池（draftPool）在赛季末生成，经理有约 7 日窗口集中探查。

11.1 选秀探查窗口

阶段时间可用探查
选秀池生成赛季末 DAY 4选秀池 ~60 人公布，初始 fog ±15（已有赛事可见度收窄）
联合试训DAY 5-6集体浅探：所有选秀池球员 fog 各收窄 ±3（免费，每队 1 次）
单独探查DAY 5-10针对顺位目标球员探查/潜力探查/探针
选秀夜DAY 11探查截止；按战绩倒序选秀

11.2 选秀探查策略

  • 顺位锁定：经理知道自己选秀顺位（战绩倒序），只探查顺位附近的目标。
  • 集中投入：选秀前探查预算集中消耗——一次选秀探查投入可能占赛季预算 40%。
  • 信息不对称：其他经理也在探查，但各自探查结果私有。某球员被多队看好时，选秀顺位竞争上升。
  • fog 揭晓：选秀签约后，球员真实值部分揭晓（能力值 ±2，Peak 仍 ±5 直到生涯展开）。

12自由球员与对手探查

12.1 自由球员探查

  • 目标：自由球员池（freeAgentPool）中的球员。
  • 动机：签约前评估是否值得合同，避免签下 fog 内低点球员。
  • 特点：自由球员多为成人（19+），fog 相对易收窄；但有"衰退轨迹"风险（26+ 老将）。
  • 探针配合：签约前可使用试训邀请 + 医疗体检 + 心理评估三件套，将风险降至最低。

12.2 对手探查

  • 目标：其他球队名单内球员（非本队）。
  • 动机：赛前了解对手核心球员状态；转会窗评估交易目标。
  • 限制：对手名单球员 fog 收窄更难（distancePenalty 高，且球员在他人队内不配合试训/体检）。
  • 产出：赛前对手探查报告可帮助战术针对性布置（战术系统条件规则可用 fog 数据）。

12.3 对手探查的反制

  • 信息保密：经理可设置队内球员为"保密状态"，提高对手探查的 distancePenalty ×1.5。
  • 反球探：雇佣情报网络分支球探可发现"谁在探查我方球员"，获得对手意图线索。
  • 假情报（高阶）：高等级情报网络球探有概率向对手投放虚假特质线索（误报率提升）。

13对阵亲历

对阵亲历是 fog 收窄的免费途径——与某球员交手后，基于其实际表现收窄 fog。

13.1 对阵收窄机制

── 对阵亲历 fog 收窄 ── after game where player played against myTeam: observedAbilities = inferFromStats(player.gameStats) // 如：三分 5/8 → ThreePT fog 收窄 ±3 // 如：0 抢断 4 失误 → Defense/Handling fog 收窄 ±2 for ability in observedAbilities: player.fog[ability] = max(3, player.fog[ability] - 3) // fogFloor = 3（对阵亲历比球探报告更准但仍非真实值） // Peak fog 不收窄（单场表现不揭示天花板）

13.2 对阵亲历的特点

  • 免费：不消耗预算与球探时间。
  • 仅赛中能力：只收窄该场表现相关能力（如得分手探查不到防守）。
  • 样本偏差：单场表现有随机性，对阵亲历可能收窄到"表现值"而非"真实值"。
  • 累积：多次交手累积收窄，长期对手的 fog 可收窄至 ±3（接近真实）。

15报告衰减与失效

球探报告不是永久的——球员能力会变化，旧报告逐渐失准。

15.1 freshness 衰减

── 报告新鲜度衰减 ── // 每日 16:00 翻天时 report.freshness = report.freshness * 0.97 // 每日衰减3% // freshness 影响报告可信度 effectiveConfidence = report.confidence * report.freshness // 球员能力变化时加速衰减 if (player.abilityChanged > 2): report.freshness *= 0.85 // 能力变化大的球员报告更快失准

15.2 报告失效

freshness状态表现
1.0-0.8新鲜正常显示 fog 区间
0.79-0.5陈旧fog 区间标注"陈旧"，建议重新探查
0.49-0.2过时fog 区间标注"过时"，区间视觉扩大 1.5 倍
<0.2失效报告归档，不再提供 fog 收窄；球员回到基础 fog

15.3 重新探查

  • 对报告过时/失效的球员重新探查，新报告覆盖旧报告的衰减状态。
  • 重新探查的 fogNarrow 基于当前 fog（已因衰减扩大），可能"探了还是宽"——需投入足够次数。
  • Watchlist 跟踪的球员 freshness 衰减更慢（×0.99 而非 ×0.97）。

17异常处理与边界规则

17.1 球探状态异常

异常处理
球探被解雇/转职进行中任务中断，预算不退，部分产出（按时长比例）
目标球员被交易/退役任务自动中止，预算退 50%
目标球员离开世界任务中止，预算全额退
预算不足任务指派被拒；进行中任务不受影响
球探体力耗尽任务产出质量下降（fogNarrow ×0.5），建议轮休

17.2 揭晓规则

  • 签约揭晓：球员签约本队后，能力值 fog 收窄至 ±2（仍非真实值，需训练/比赛逐步揭晓）。
  • 选秀揭晓：同签约。
  • 对阵揭晓：交手后按 §13 收窄。
  • 真实值：永远只有服务端持有。球员能力变化（训练/伤病/年龄）不影响已揭晓 fog 的范围，但 est 会随真实值漂移而微调。

17.3 信息隔离

  • 报告私有：各队球探报告互相不可见，确保信息不对称。
  • Watchlist 私有：各队关注名单不可见。
  • 预算私有：各队球探预算余额不可见。
  • 反制线索可见：反球探可发现"谁在探我方球员"，但不知道探查内容。
