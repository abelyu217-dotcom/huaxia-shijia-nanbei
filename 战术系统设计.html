战术是方向，不是遥控器。玩家通过战术设置指导球队的进攻倾向、防守策略、轮换节奏和关键球处理，但具体每回合的出手选择仍由球员依据自身能力、情境与对位自行决策。本系统定义战术如何作为"权重修改参数集"注入 sim engine。

1设计原则与架构

1.1 核心设计命题

战术是方向，不是遥控器：玩家设定的是球队"打法倾向"——进攻偏外线还是内线、防守压迫还是收缩、节奏快还是慢——而非逐回合操控。球员依据自身能力 + 战术倾向 + 对位 + 情境自行决策每个回合的行动。这让战术真正"活"起来：同一个"外线进攻"战术，给一支三分射手群和给一支内线猛兽队，会打出截然不同的比赛。

1.2 战术系统的三层深度

L1 基础三选即用 · 新手友好
L2 高级角色/轮换/条件规则
L3 Clutch战术卡/半场调整/对位针对性
层级面向用户核心内容解锁条件
L1 基础新手 / 休闲玩家进攻倾向 + 防守倾向 + 节奏，三选即用默认解锁
L2 高级核心玩家战术角色分配、轮换逻辑、条件规则、多套存档经理声望 Lv.3
L3 Clutch硬核玩家Clutch 战术卡、半场调整、对位针对性防守经理声望 Lv.6

1.3 战术数据结构

战术在 sim engine 中体现为一个 MatchTactics 结构，sim 引擎只消费这个结构，不区分默认战术与 per-game 战术。

MatchTactics = { // L1 基础 offenseTendency: "outside" | "balanced" | "inside", defenseTendency: "press" | "balanced" | "pack", tempo: "fast" | "balanced" | "slow", // L2 高级 roles: [TacticalRole; 12], // 每名球员的战术角色 rotation: RotationConfig, // 轮换设置 pickRollFreq: "low" | "mid" | "high", threeFreq: "low" | "mid" | "high", fastBreakPref: "low" | "mid" | "high", matchupOverride: [MatchupPair; 5], // 自定义对位 conditionalRules: [ConditionalRule], // 条件规则列表 // L3 Clutch clutchDeck: [ClutchCard; 3], // Clutch 战术卡组（3 张） halftimeRules: [HalftimeRule; 2], // 半场调整规则（2 槽） targetDef: TargetDefense?, // 对位针对性防守 // 元数据 name: string, // 战术存档名 isDefault: bool, // 是否为默认战术 }

1.4 战术→Sim 参数注入流程

战术参数通过 sim engine 的 Modifier Layer (L4) 注入。每回合开始时，sim 按以下优先级叠加所有有效参数：

// 参数叠加优先级（低→高，高优先级覆盖低优先级） effectiveParams = mergeByPriority( ① baseConfig, // sim 全局默认配置 ② tactics.L1, // 基础三选参数 ③ tactics.L2, // 高级参数（角色/轮换/频率） ④ conditionalRules, // 满足条件的条件规则（按 priority 降序） ⑤ halftimeRules, // 半场调整（仅下半场生效） ⑥ clutchCards, // Clutch 卡（仅 Clutch 时段生效） ⑦ targetDef, // 对位针对性防守（全程或指定时段） ) // 后者覆盖前者同参数；不同参数叠加共存

3.3 战术存档系统

  • 存档上限：默认 5 套存档，VIP 额外 +5 套
  • 存档命名：自定义名称，如"主场跑轰""季后赛防守"
  • 快速切换：比赛日前可从存档库选择一套作为本场战术
  • 复制与模板：可复制已有存档进行修改；提供 6 套预设模板（跑轰/铁桶/全能/魔球/绞肉/防守反击）
  • Per-game 覆盖：可为指定赛程设置 per-game 战术，优先于默认存档

5.3 角色冲突规则

约束：每名球员只能有一个进攻角色和一个防守角色。主攻点/副攻点全队最多各 2 人。组织核心全队最多 1 人。护筐者全队最多 1 人。这些限制防止单一角色堆叠导致的策略扭曲。

6条件规则系统规格

条件规则是战术系统的核心深度机制：预设一组条件 + 一组参数修改，当比赛中满足条件时自动触发。这让战术从"静态设定"变为"动态响应"。

6.1 规则结构

ConditionalRule = { id: string, name: string, // 玩家自定义名称 enabled: bool, conditions: [Condition], // 条件列表（AND 关系：全部满足才触发） actions: [RuleAction], // 触发后执行的参数修改 priority: u8, // 优先级 1-99，高优先级覆盖低优先级 cooldown: u16, // 冷却回合数（触发后 N 回合不再触发，防抖） maxTriggers: u8, // 最大触发次数（0=无限） } Condition = { type: ConditionType, op: "==" | "!=" | "<" | "<=" | ">" | ">=", value: number | string, } RuleAction = { param: string, // 修改的 sim 参数名 op: "set" | "multiply" | "add", value: number, }

6.4 条件规则示例

6.5 冲突解决规则

多条规则同时满足时，按以下规则解决参数冲突：

  • 不同参数：叠加共存（如一条改三分倾向、一条改防守策略，两者同时生效）
  • 同参数同 op：高 priority 覆盖低 priority（不叠加）
  • 同参数不同 op：按 op 类型顺序执行——先 set 再 multiply 再 add
  • 同 priority：按规则列表顺序，后者覆盖前者
  • 冷却与次数：规则触发后进入冷却期（cooldown 回合），期间不再检查该规则；maxTriggers 到达后规则永久禁用
规则上限：每套战术存档最多 8 条条件规则。这既是性能约束（sim 每回合检查所有规则），也是设计约束（防止玩家写"万能战术"覆盖所有情境，失去涌现性）。

7.4 Clutch 卡与 Clutch 球员修正的交互

Clutch 球员修正（基于性格和特质，见 Sim Engine §13.3）与 Clutch 战术卡叠加生效：

// Clutch 时段最终参数 = 战术卡覆盖 × 球员性格/特质修正 effectiveClutchMod[p] = clutchCardMod × clutchPlayerMod[p] // 例：冷血杀手球员 + 三分绝杀卡 // shotProb: baseRate + abilityBonus + (clutchCard +0.05) + (coldBlood +0.08) = +0.13 // actionWeight[three]: ×3.0 (card) × 1.3 (coldBlood trait) = ×3.9
设计意图：Clutch 卡是"战术方向"，球员性格/特质是"执行力"。好的战术 + 好的关键球球员 = Clutch 统治力。但即使最好的战术卡也无法让"玻璃心"球员在关键时刻不退缩——这让选材和战术设计成为互补的两个维度。

8.2 目标选择

TargetDefense = { type: "double_team" | "protect_rim" | "switch_all" | "sag_off" | "perimeter_lock" | "post_deny", target: playerId?, // 对方球员ID（protect_rim/switch_all 不需要指定目标） duration: "full_game" | "clutch_only" | "conditional", condition: Condition?, // duration=conditional 时的触发条件 }
  • 全程：从比赛开始到结束持续生效（适用于你确信策略有效的对手）
  • 仅 Clutch：仅在 Clutch 时段生效（保守选择，避免全程被对手适应）
  • 条件触发：满足预设条件时生效（如"对方核心得分 ≥ 20 时包夹"）

// 例：基础"收缩" + 对位"外线锁死"对方核心射手 // 收缩：three defensePenalty ×0.6（全队放空外线） // 外线锁死：目标球员 three defensePenalty ×1.3（锁死该球员外线） // 结果：对方核心被锁死，但其他球员外线被放空 // 这是一种"赌角色球员投不死我"的策略——合理但有风险

9.5 自动 vs 手动

  • 自动模式：玩家在比赛前预设好条件和动作，中场时系统自动检查并执行。适合不想中断观赛体验的玩家。
  • 手动模式：中场时弹出调整界面，玩家看到上半场 Box Score 后手动选择 0-2 处调整。适合喜欢"中场教练"体验的玩家。
  • 默认：L3 解锁后默认为手动模式；可在设置中切换为自动。

12Per-game 战术与备战系统

情报限制：对方战术存档（具体条件规则/Clutch 卡/对位针对性）始终不可见——只能从比赛数据推测。这保留了战术博弈的不确定性和心理战维度。

12.3 球探报告辅助

球探系统（策划方案 §10）的 Fog 机制与备战情报联动：

  • 对方球员的 Fog 收窄后，备战情报中的数据更精确（能力估值误差更小）
  • 对阵亲历（交过手）自动收窄 Fog → 再打同一对手时备战信息更准
  • 可派球探专门探查下一场对手 → 赛前获得对方球员的精确能力估值

15战术平衡性设计

15.1 平衡原则

原则含义实现方式
无最优解不存在一套"最强战术"每套战术都有明确代价（跑轰费体力、铁桶放三分、压迫犯规多）
克制关系战术间有循环克制外线进攻克收缩防守；内线进攻克压迫防守；快攻克慢节奏但被深度轮换克
阵容匹配战术效果取决于阵容外线战术需要三分射手；压迫防守需要敏捷防守者；没有合适球员时战术效果打折
涌现性比赛结果不可预测随机项 + 对位博弈 + 条件规则触发 → 同一 matchups 多场结果有合理方差

15.2 战术克制矩阵

进攻\防守压迫平衡收缩
外线中立：压迫增加失误但也给空位中立进攻优势：收缩放空三分
平衡防守优势：压迫打乱平衡进攻中立中立
内线进攻优势：压迫犯规多 + 内线造杀伤中立防守优势：收缩护筐克内线

15.3 节奏克制

进攻节奏\对方轮换主力优先均衡深度轮换
快进攻优势：快节奏消耗对方主力体力中立防守优势：深度轮换不怕消耗
平衡中立中立中立
慢防守优势：慢节奏让主力优势发挥中立进攻优势：慢节奏减少回合数压制深度轮换优势

15.4 回归测试校准

战术平衡性通过 Sim Engine §19 的回归测试框架验证：

  • 战术克制验证：外线战术 vs 收缩防守的胜率应显著高于外线 vs 压迫防守
  • 无最优解验证：27 种基础组合的相互对局中，没有一种组合胜率显著高于所有其他组合
  • 阵容匹配验证：外线战术 + 三分射手阵容 的胜率应显著高于 外线战术 + 内线阵容
  • Clutch 卡验证：有 Clutch 卡的球队在 Clutch 频率场景中胜率应高于无卡球队
  • 条件规则验证：合理条件规则的球队在特定情境（落后追分等）中逆转率应更高
