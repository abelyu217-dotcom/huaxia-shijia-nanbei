1设计原则

核心原则：让对抗与社交自然涌现，而非强塞社交功能。HWO 不是社交游戏——它是篮球经理游戏。社交与对抗是"多人在线"自然产生的副产品：你和同一组的人反复比赛就产生宿敌，你反复交易就建立人脉，你反复夺冠就积累声望。系统只负责"识别并记录"这些自然涌现的关系，不强制玩家社交。
① 涌现而非强塞 自然
宿敌、人脉、声望都从游戏行为中自然涌现——反复对阵、反复交易、反复夺冠。系统不要求玩家"加好友""建公会"。
② 对抗优先于社交 张力
HWO 的核心张力是竞争而非合作。宿敌比好友重要；交易博弈比互助重要。社交是对抗的副产品。
③ 留痕可追溯 档案
所有对抗历史（交易/对阵/宿敌）永久留痕。经理档案是"江湖地位"的体现，影响他人对你的判断。
④ 可选可关闭 友好
聊天/垃圾话/颁奖都是可选的。玩家可关闭社交功能，纯玩经营。社交不强制、不惩罚不参与者。

2.2 与球员关系系统的区分

重要区分：关系系统（球员家庭与人际关系）是球员层面的社交——球员与球员之间的关系（家庭/师徒/队友/宿敌）。本系统是经理层面的社交——经理与经理之间的关系（宿敌/人脉/交易伙伴）。两者独立但可交叉（如两队经理是宿敌，且各自核心球员也是宿敌——双重对抗叙事）。

4宿敌系统

深化策划方案 §16.2。宿敌是自然涌现的对抗关系——反复对阵且比分接近的两队，系统标记为宿敌。

4.1 宿敌生成算法

── 宿敌点数累积 ── function updateRivalry(teamA, teamB, matchResult): rivalryPoints = 0 // 分差越小，点数越高 margin = abs(matchResult.scoreA - matchResult.scoreB) if (margin <= 3): rivalryPoints += 3 // 绝杀级 elif (margin <= 8): rivalryPoints += 2 // 接近 elif (margin <= 15): rivalryPoints += 1 // 正常 else: rivalryPoints += 0 // 碾压不计 // 季后赛对阵加倍 if (matchResult.isPlayoff): rivalryPoints *= 2 // clutch 时刻加分 if (matchResult.hadClutchMoment): rivalryPoints += 2 // 更新双向宿敌点数 rivalry[teamA][teamB] += rivalryPoints rivalry[teamB][teamA] += rivalryPoints // 自然衰减（每季 -10%） rivalry[teamA][teamB] *= 0.9 at season end

4.3 宿敌的数值效果

宿敌不只是叙事标签——它有轻微数值效果，模拟"德比战更拼命"：

等级clutch 加成球迷热情叙事
死敌+5 双方对阵日 +10"宿敌对决"头条；历史战绩回溯
宿敌+3 双方对阵日 +5赛事快报高亮
关注+1 双方—正常
普通——正常
设计约束：宿敌加成是双向对称的——双方都获得相同 clutch 加成。这不是"谁更强"，而是"双方都更拼命"。加成幅度小（+1~5），不改变实力对比，只让比赛更激烈。

4.4 德比与生死战

  • 德比：同城/同区球队自动德比标记——宿敌点数起点 +20（天生对手）。
  • 升降级生死战：决定升降级的关键对阵——单场宿敌点数 ×3；胜负直接改变两队命运。
  • 季后赛宿敌：季后赛对阵的宿敌点数 ×2——季后赛是宿敌的最高温时刻。

4.5 宿敌的兴衰

  • 宿敌点数每季自然衰减 10%——不持续对抗就会淡化。
  • 一方降级/迁移 → 宿敌"暂停"（点数冻结但不增长）。
  • 双方再次同联赛 → 宿敌"恢复"。
  • 长期不再对阵（≥5 季）→ 宿敌"终结"，记入历史："曾经的宿敌"。

5交易谈判的社交维度

深化策划方案 §16.3。签约转会 §7 已定义交易谈判的操作机制（三轮还价/心理战）。本节补全其社交维度——谈判历史公开、社区评价、交易声誉。

5.1 交易历史公开

  • 所有完成的交易记录在双方经理的公开档案中。
  • 交易记录展示：日期、筹码、当时 fog 信息、事后表现。
  • "这笔交易谁亏了"：交易完成 N 季后，系统按球员实际表现回溯评估——"赚了/亏了/双赢/双输"。
  • 这是社区谈资的核心素材——"XX 经理又坑人了""这笔交易其实是双赢"。

5.2 交易声誉系统

── 交易声誉计算 ── tradeReputation = clamp( sum(trade.eval for trade in history) / count(history), -1.0, 1.0 ) // 单笔交易评估（事后回溯） trade.eval = evaluateTrade(trade, seasonsAfter=2) // +1 = 明显赚了（换来的球员远超预期） // 0 = 公平/无法判断 // -1 = 明显亏了（换来的球员水了/送走的球员爆了）

5.3 交易声誉的影响

声誉区间标签影响
≥0.5交易大师AI 更愿接受你的报价；交易邀请增多
0.2~0.5可靠伙伴正常交易环境
-0.2~0.2—正常
-0.5~-0.2精明商人AI 报价更保守；谨慎交易
≤-0.5坑人贩子AI 拒绝部分报价；交易邀请减少；社区负面评价

5.4 fog 不对称的社交后果

核心博弈：球探系统的 fog 不对称让交易天然带"信息差"——你知道你球员的 fog 比对手窄。用 fog 优势"坑"对手会降低交易声誉。但有时"坑"只是因为对手 fog 太宽（自己探查不够），并非恶意。系统无法区分"恶意坑"与"信息差"——因此交易声誉是客观事后评估，不区分动机。这迫使玩家在"利用信息差最大化收益"与"维护交易声誉长期合作"间权衡。

6联盟内社交

深化策划方案 §16.4。联盟内社交是可选功能——同组联赛的经理可交流。

6.1 组内聊天频道

  • 范围：同组联赛（16 队）的经理可加入组内聊天频道。
  • 可选：默认关闭；玩家可主动开启。
  • 可关闭：任何玩家可随时关闭聊天——纯玩经营不受影响。
  • 内容：赛前垃圾话/赛后讨论/交易试探/闲聊。

6.2 垃圾话机制

  • 赛前垃圾话：赛前可向对手发送预设垃圾话（不可自定义文本，防骚扰）。
  • 效果：接收方可选择"无视"（无效果）或"回击"（双方 clutch +2——"被激怒更拼命"）。
  • 赛后：胜方可发"赛后感言"（预设）；负方可"认输"或"下次等着"。
  • 预设文本：所有垃圾话/感言均为系统预设选项，不可自定义——防滥用。

6.3 交易试探频道

  • 组内设"交易试探"频道——经理可发布"我在找 XX 类型球员""我有 XX 可出"。
  • 这是非正式交易意向发布，不构成报价——正式交易走签约转会 §7 流程。
  • 降低交易匹配成本——不用逐个私聊试探。

6.4 联盟公告板

  • 组内设公告板——展示本组重要事件（升降级/重大交易/宿敌对决）。
  • 系统自动生成，不需玩家维护。
  • 让不聊天的玩家也能感知联盟动态。

7世界排名与跨联赛声望

深化策划方案 §16.5。世界排名是跨联赛的经理声望榜——激励玩家冲击顶级联赛与多代王朝。

7.1 声望积分公式

── 经理声望积分 ── reputation = titles * leagueTierBonus * 100 + runnerUps * leagueTierBonus * 40 + playoffAppearances * leagueTierBonus * 15 + dynastiesBuilt * 200 + hofPlayersTrained * 80 + seasonsManaged * 5 - relegations * 20 // 联赛层级加成：T1=2.0, T2=1.5, T3=1.2, T4=1.0 // T1 冠军 = 200 分；T4 冠军 = 100 分——顶级联赛成就更值钱

7.2 世界排名榜

  • 按 reputation 降序排列的世界经理排名。
  • 分层展示：TOP 100 / TOP 500 / 全榜。
  • 赛季更新：每赛季末更新排名。
  • 赛季进步奖：声望进步最快的经理获"进步奖"标签。

7.3 声望的用途

用途说明
世界排名跨联赛声望榜
交易谈判高声望经理的报价更受 AI 信任（tradeReputation 联动）
经理标签声望阈值触发标签（"冠军教头"等）
新世界起始传奇经理在新世界获起始声望加成（王朝系统 §11.3）
叙事引用"声望 XX 的名帅"作为叙事素材

8经理人脉网络

关系系统是球员层面的关系网络。本节定义经理层面的人脉——从反复交易/对阵中自然涌现。

8.1 人脉类型

类型涌现方式效果
交易伙伴完成 ≥3 笔公平交易后续交易 AI 更愿接受；交易试探优先匹配
宿敌§4 宿敌系统对阵 clutch 加成；叙事高亮
师徒资深经理与新手同组 ≥2 季新手可"请教"获得小幅运营建议（非数值）
同盟≥2 经理互相标记"友好"（双向确认）交易试探优先；信息分享（可选）

8.2 人脉网络可视化

  • 类似关系系统的力导向图——节点为经理，连线为人脉类型。
  • 经理可查看自己的人脉网络。
  • 不展示他人人脉：只看自己的——保护隐私。

8.3 人脉的边界

关键约束：人脉不产生数值优势——交易伙伴只是"更愿交易"不是"打折交易"；同盟只是"优先试探"不是"内幕交易"。人脉是社交便利，不是竞技优势。防止人脉网络演变为"小圈子垄断交易"。

9观赛与互动

策划方案 §19 提及实时观战（WebSocket/SSE 推送 PBP）。本节补全观赛的社交互动。

9.1 观赛模式

  • 实时观赛：sim 运行时逐回合推送 PBP，可实时观看。
  • 回放观赛：赛后可看完整回放（VIP 额外存档）。
  • 关键球回放：自动生成 clutch 时刻集锦。

9.2 观赛互动

互动说明影响强度
预设反应观赛时发预设表情/反应（👏🔥😢等）否 纯社交
关键球标记观众标记"这一球太关键了"否 纯社交
赛后点赞赛后给对手/精彩球员点赞否 纯社交
垃圾话赛前预设垃圾话（§6.2）微 clutch +2 双方

9.3 观赛不影响比赛

关键设计：观赛互动是纯社交——反应/标记/点赞不影响 sim 结果。sim 在服务端权威执行（策划方案 §19），观赛只是"看"，不是"参与"。唯一有微弱影响的是赛前垃圾话（clutch +2 双方），且是双向对称的——不改变实力对比。

11对抗叙事自动生成

王朝系统 §13 定义了"大时间尺度"的叙事弧线。本节定义"对抗尺度"的叙事——宿敌对决、交易博弈、赛季黑马。

11.1 对抗叙事类型

叙事触发叙事节点
宿敌对决弧死敌对阵历史战绩回溯→本赛季恩怨→对决→胜负→"又添一笔"
交易博弈弧重大交易事后评估交易达成→事后表现→"谁赚谁亏"→社区评价

  • 引用王朝系统年代史——"XX 王朝曾统治联赛..."

12反骚扰与社区治理

12.1 防骚扰设计

预设文本 防滥用
所有垃圾话/感言均为系统预设选项，不可自定义文本——防止言语骚扰。
可选可关闭 自主
聊天/垃圾话/反应均可关闭。关闭后不受任何社交干扰。
屏蔽名单 隔离

举报机制 治理
可举报违规行为（如利用交易试探频道发不当内容）。

12.2 交易公平治理

  • 失衡交易复核（签约转会 §12）：系统自动检测失衡交易，触发仲裁审查。
  • 联盟仲裁人（三身份 §5.8）：职业人可担任仲裁人，裁决交易申诉。
  • 恶意交易惩罚：反复恶意失衡交易的经理，交易声誉降至"坑人贩子"，AI 拒绝交易。

12.3 反作弊

  • sim 服务端权威（策划方案 §19）：比赛结果不可篡改。
  • 多账号检测：检测同一玩家多账号同世界——禁止（防自我交易套利）。
  • 交易模式检测：检测"反复单向交易"模式（A 反复给 B 好球员）——触发审查。

14AI 社交行为

14.1 AI 经理的社交模拟

  • AI 宿敌：AI 球队也参与宿敌系统——与玩家或与其他 AI 形成宿敌。
  • AI 交易声誉：AI 经理有交易声誉值；按声誉调整对玩家报价的接受度。
  • AI 垃圾话：AI 经理偶尔发预设垃圾话（按"性格"——有的 AI 爱喷，有的沉默）。
  • AI 投票：AI 经理参与社区票选（按"偏好"投票——如偏好进攻型球队）。

14.2 AI 性格分化

AI 性格社交行为
沉默型不发垃圾话；不聊天；只交易
友善型偶尔发友好感言；愿公平交易
好斗型常发垃圾话；交易更激进
精明型不发垃圾话；交易极度精明；声誉偏负

15异常处理与边界规则

15.1 社交异常

异常处理
经理退游档案存入年代史（王朝系统 §11）；宿敌"暂停"；AI 接手球队
经理迁移世界原世界宿敌"终结"；人脉标记"远"；新世界重新积累
同组人数不足（AI 填充）AI 经理填充（世界结构 §8）；社交功能正常（AI 模拟社交）
屏蔽后同组屏蔽有效；不收对方任何社交内容；交易邀请也屏蔽
票选投票率不足AI 补票（按 AI 偏好）；确保奖项产生

15.2 跨世界隔离

  • 社交世界内封闭——A 世界的宿敌/人脉在 B 世界无效。
  • 世界迁移后社交重置——新世界重新积累。
  • 经理档案跨世界可查（公开档案），但社交关系不跨世界。
